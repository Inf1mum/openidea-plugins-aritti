# Spring Initializr Launcher

Starts Spring Boot projects from OpenIDEA through a Spring Initializr server.
MIT; see `LICENSE`.

## Tool window

The Spring Initializr tool window (right) offers a Project form: server URL (default `https://start.spring.io`), build (Maven, Gradle - Groovy, Gradle - Kotlin), language, Spring Boot version (blank for the server's default), group, artifact, name and package name (both follow the artifact until changed; the package is `group.artifact` lower-cased without `-`), description, packaging, Java version and dependencies (comma-separated ids such as `web,data-jpa`). The form is kept per project and server in plugin storage; Reset restores form defaults in the current scope. The form displays the server's declared build, language, packaging and Java choices once metadata is available; choices absent from non-empty server lists are rejected at generation.

The Spring Initializr: Open start.spring.io command opens the site. Project and Dependencies keep Generate Project as the primary toolbar action; More Actions… opens the native action picker for the other workflows (CLI launcher, browser exploration, source-only import, reviewed-folder opening, Boot version selection, reset/reload, catalogue refresh). Only currently enabled actions appear; a changed form, project scope or saved-state snapshot while the picker is open refuses the selection.

## Dependencies

The Dependencies section (toolbar button "Dependencies (N)") browses the server catalogue as a tree: a Selected (N) node with the chosen ids, then the collapsed categories with a check on chosen dependencies. Double-click or Enter toggles a dependency; the ids stay editable in the Project section's `dependencies` field. Search… filters by name, description and id (case-insensitive) until Clear search; Clear all asks first; Refresh reloads the catalogue. The Generate buttons work in both sections.

The catalogue comes from `https://start.spring.io/metadata/client` (optional `net:start.spring.io` capability), loaded from a saved snapshot when available and otherwise fetched once on first opening; Refresh requests new metadata. For other servers, or without the capability, the tree shows a message and Selected keeps working; type the ids manually.

Dependencies whose `versionRange` (or legacy `compatibilityRange`) excludes the current Spring Boot version are hidden; a chosen one stays under Selected marked "(not compatible with <version>)". Supported ranges are numeric versions with M/RC/SNAPSHOT qualifiers, lower bounds and open/closed intervals. Ranges that do not parse completely in the supported integer model (overflow, malformed/trailing components, unsupported qualifiers, contradictory intervals) are not compared partially; the dependency shows "compatibility range unverified". Generation and CLI arguments also reject incompatible choices. The server remains authoritative: unknown ranges, missing defaults/lists and unknown manually entered ids are unverified. Java version is the requested language level, not an installed-JDK check.

When the loaded snapshot declares a default Boot version, leaving Boot blank pins that version in the outgoing request (keeping it aligned with compatibility checks even if the server default later changes); otherwise blank is left to the server.

## Generation

- **Generate Project** opens `<server>/starter.zip?…` in the browser, which downloads the project zip. Blank options are left out; the status line says what is missing (an http(s) server URL, a group or an artifact). Works project-free; the browser path remains manual download/extraction.
- **Explore in Browser** opens the server's page (`<server>/#!…`) with the same options.
- **Generate with Spring Boot CLI** opens a keyed IDE terminal running `spring init` with the form's explicit service (`--target`), build, type, language, Boot and Java versions, packaging, coordinates, dependencies and `--extract` into a directory named after the artifact. It needs the optional `process:spring` and `project.read` capabilities, an identifiable open project, and the Spring Boot CLI on the PATH; without the capability a notification says so and the browser download runs instead. Group, artifact, name, versions and package name are checked against letters, digits, `.`, `_` and `-`; values reach `spring init` as separate program arguments, never through a shell line. The preflight requires the fresh project to match the form owner and both root/output-child owners; the non-hidden artifact child is bounded to 128 bytes and must not already exist; the terminal uses the project root as cwd; a refused preflight launches nothing (the checks are preflight, not exclusive creation).
- The CLI adapter supports `maven-project`, `gradle-project` and `gradle-project-kotlin` explicitly; other types use the browser action. When the saved catalogue declares a type's `tags.build`/`tags.format`, they must agree with the adapter's build; missing tags remain unknown.
- The CLI run section offers a separate reviewed managed Start, explicit Check status/output and Cancel: one child, bounded 32 KiB observed output, overflow requests stop, failed stop blocks duplicate starts, scope changes and deactivation request stop. No automatic idle deadline, exclusive target reservation, cleanup, generated-tree validation or project opening follows from exit status.
- After a successful CLI exit, **Review and Open Generated Folder…** inspects the physical tree, shows a complete path/size/mode/hash manifest, rechecks it, and requests the normal project trust/open flow. Exit 0 alone never opens a folder or certifies a build.
- **Generate and Open…** (also the Generate and Open Complete Project command) downloads the server ZIP and uses an optional approved `python3` (3.8+, isolated mode) to extract anywhere the approved process can access, including outside the current project, project-free. After download/inspection you review the canonical destination, archive SHA-256 and complete manifest before any writes. Binary wrappers and empty directories are retained; executable files get mode 755, others 644; special modes, links, traversal, case collisions, encrypted archives and conflicts are refused; up to 512 entries, 8 MiB compressed, 32 MiB expanded, 4 MiB per file, review within the host's 16 KiB confirmation limit. Extraction goes into a private staging directory and commits with a kernel-exclusive rename (macOS `renamex_np`, Linux `renameat2`, Windows non-replacing `os.rename`; unavailable profiles fail visibly). Failures leave staging for inspection and never open a partial project; a successful commit requests the normal trust/open flow. Cancelled runs may leave a `.initializr-*` staging folder or a fully committed project; neither is deleted automatically. A new generation retires the preceding successful-run candidate.

## Add Spring Boot Starters

**Spring Initializr: Prepare Add Spring Boot Starters** (Tools menu) prepares a version-bound 15-minute metadata cache for a supported current Maven POM or Gradle build; **Preview Add Spring Boot Starters…** (a source intention) then picks and previews an atomic, undoable insertion into the complete resulting file.

- Maven support: a literal three-number GA `spring-boot-starter-parent` with empty `relativePath`, or a parentless standalone POM whose sole management entry is the literal GA `spring-boot-dependencies` BOM (`type=pom`, `scope=import`). Absent, self-closing or empty `<dependencies>` containers are handled; insertion derives indentation from source and the result is revalidated. Maven model 4.0.0; default/no namespace only; profiles, repositories, modules, other dependency management and competing `.mvn` config files along the bounded ancestry are refused; only `java.version` and `project.build.sourceEncoding` properties are admitted; files capped at 12 KiB, 512 XML nodes, 32 levels. Duplicate/misplaced XML declarations, malformed comments, reserved-case PI targets and unbound `xsi` attributes are refused before metadata fetch. Pickers include only declared-compatible plain `org.springframework.boot` starters with no explicit version/BOM/repository requirement and a known scope; up to eight distinct advertised IDs; existing group/artifact pairs are skipped; no version, repository or scope migration is guessed.
- Gradle support: the owning project's exact `build.gradle`/`build.gradle.kts` with the Java plugin, a literal three-part Boot plugin version advertised by the catalogue, and literal `io.spring.dependency-management` version `1.1.7`; optional literal coordinates, numeric Java toolchain, `mavenCentral()` and the conventional JUnit Platform test task; a matching-dialect settings file with only `rootProject.name`; 12 KiB cap. Compile/runtime/test map to `implementation`/`runtimeOnly`/`testImplementation`; `provided` is refused. Dynamic expressions, extra plugins, version catalogs, properties/build logic, competing builds and additional BOM/platform declarations are outside the adapter; provider discovery does not fetch or execute Gradle.
- The intention binds the exact project, path, document version/text, server and metadata snapshot, rechecks visible source and competing configuration before selection and after confirmation, and returns one current-file insertion. The preview contains the complete exact resulting file, preserves LF/CRLF and existing bytes, and refuses previews beyond the confirmation limit. Cancel, expired/forged/replayed actions and changed ownership/metadata/source return no edit. Unsaved current text is supported.

## Source-only Maven ZIP import

**Prepare Maven Source-only Import…** (or Tools → Prepare Maven Source-only Import) uses the current project/server form and saved metadata; it requires an open project, advertised Maven/Java/Jar/Boot/Java-version choices and known dependency compatibility. Choose an existing parent directory inside that project; the target is its vacant artifact-name child. A first confirmation shows the exact URL and target and states that no process or disk extraction runs; the ZIP is downloaded only by this explicit command and validated entirely in memory. **Preview Import Maven Sources…** shows the complete manifest, every file's UTF-8 content and byte count, and the known wrapper exclusions (`mvnw`, `mvnw.cmd`, `.mvn/wrapper/maven-wrapper.properties`, `.mvn/wrapper/maven-wrapper.jar` — their presence is listed). The result is one atomic FileAction of at most 32 non-overwriting creates; collisions, changed owner/form/server/metadata, a stale anchor document, cancellation or an oversized preview (12 KiB per file, 16 KiB confirmation) return no operation — larger projects are refused rather than summarized.

Only ordinary single-disk classic ZIP (stored/deflated) is supported; 1 MiB archive, 64 entries, 128 KiB each, 512 KiB declared total, bounded compression ratio; symlinks/devices, unsafe paths, duplicates, non-UTF-8 and binary files are refused. The root POM must match the chosen group/artifact/Boot parent, echo the selected literal `java.version`, use jar or omitted packaging, contain every selected plain Boot-managed starter with its declared scope (up to 64; version echoes required via `/dependencies?bootVersion=`), and a source path under the chosen package must exist. **Open Reviewed Source Folder…** independently verifies all expected paths against project-visible text and only then requests the normal trust/open flow in a new window; unsaved buffers can mask disk contents, and build/runtime state is not certified.

Innermost-project ownership of the selected parent, its ancestry, the target and every planned/verified source path is checked before fetch and rechecked around the final review; a nested foreign owner refuses without operations.

## State, bounds and permissions

Form fields and dependency choices persist per exact project-root + normalized server identity; switching projects or servers loads that scope; the last server is remembered per project; a saved catalogue is reusable offline; Refresh failures, malformed/duplicate choices, oversized responses and storage failures retain the previous snapshot. Server changes save the current form, persist the new selector and only then switch ownership; a failed write keeps the current form and explains the refusal. Draft conflicts and storage-denied drafts are retained in memory (at most two other scopes) with their original save baseline and recovered through confirmed Reload; unsaved drafts are not durable across restarts. Metadata and saved state use bounded JSON admission with unique decoded object keys (64 levels, 50,000 values, 2 MiB cap, 8 KiB selector envelopes).

Bounds: 2 MiB read/write state, 32 KiB changed fields, 8,192-byte fields (2,048-byte server URLs), 512 options per list, 128 categories, 4,096 dependency ids, 4,096-byte normalized absolute paths. Capabilities: required `storage`; optional `project.read`, `process:spring`, `process:python3`, `net:start.spring.io`, `editor.read`. Plugin requests target start.spring.io only.

## Not implemented

- Native New Project integration, a native JDK selector, and catalogue/Boot choices for servers other than start.spring.io (custom-server values stay manual and compatibility-unverified).
- Effective Maven/Gradle model resolution, BOM/repository migration, Gradle insertion beyond the literal adapter above, and dependency version inference.
- ZIP timestamp/nonstandard permission preservation beyond normalized 644/755 (complete ZIP path), arbitrary extraction outside the approved adapter, and automatic execution of generated builds or wrappers.
