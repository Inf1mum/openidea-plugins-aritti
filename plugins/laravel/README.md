# Laravel

Laravel support for OpenIDEA in PHP and Blade files. Features follow [Laravel's documentation](https://laravel.com/docs). MIT; see `LICENSE`.

A project counts as Laravel when it has an `artisan` file or requires `laravel/framework`. Blade highlighting, folding and the structure view come from the `aritti.blade` plugin (the IDE has no Blade grammar); without it, Blade files open as PHP and everything below still works in them.

- Blade directives: typing `@` (or `@fo`) completes Laravel's and Livewire's own directives (`@if`, `@foreach`, `@section`, `@livewire`, `@vite`, the `@end…` closers) and custom ones registered with `Blade::directive('name'` in `app/**`; the common ones insert a snippet with arguments and closer, the others insert their name only. `@@if`, `user@example.com` and `@` inside `{{ }}` are left alone; vendor-package directives aren't known. Ranking: exact prefix first, then case-folded prefix, then substring; known unmatched block context promotes closers (section closers keep `endsection` → `show` → `stop` order) and an opener before an already present unmatched closer inserts the opening line only. Comments, escaped at-signs, echoes, PHP blocks/strings, directive arguments and verbatim content are excluded; bounded to 512 KiB, 8,192 directive tokens and 128 typed prefix bytes; core completion works before the cache is warm or without project access.
- Attributes inside `<x-name ` / `<livewire:name `: the `@props([...])` of an anonymous component, class constructor parameters, or the public properties and `mount()` parameters of a Livewire class (kebab-case, `:` prefix kept); `<x-slot:` completes the variables the enclosing component's view prints.
- Containers: `app('…')`, `resolve('…')`, `App::make/get/bound('…')` and the class of `@inject('x', '…')` complete and open with the framework's aliases, literal `bind/singleton/scoped/instance/alias('x'` calls in `app/`, and the classes of `app/` (PSR-4 by namespace line); in `config/app.php` (`'providers'`) and `bootstrap/providers.php` the classes of `app/Providers` complete as `Name::class`. Vendor or run-time-registered names are unknown.
- Columns follow relations and scopes: `Post::find(1)->comments()->where('` and `Post::active()->comments()->orderBy('` complete `Comment`'s columns, and so does `$query->where('` after `$query = Post::query()...;` earlier in the file. A relation is a model method whose body calls `$this->hasMany(Comment::class)` (or `hasOne`, `belongsTo`, `belongsToMany`, `morphMany`, `morphOne`, `morphToMany`, `hasManyThrough`, `hasOneThrough`); a scope is `scopeActive` or a `#[Scope]` method; anything else stays silent. The query-variable hint stays near its binding: the nearest exact variable occurrence must be a simple assignment (4 KiB heuristic), so assignments from other methods or nearer parameter/foreach/unset uses are not borrowed.
- Eloquent members from cached sources: `Purchase::active()->first()->customer->` suggests the related model's migration columns; `Purchase::get()->` suggests collection methods. Model aliases, nullable typed parameters, simple local assignments, base-model inheritance, local scopes and known SoftDeletes methods are supported. Enum casts expose `name`, backed `value` and public instance methods; traits from `app/Traits`, `app/Concerns`, model roots and `app/Models/Concerns` contribute relations, scopes, casts and typed methods (8 nesting levels, 32 traits per model; class methods win; cycles, conflicts and adaptation blocks stay quiet); custom casts in `app/Casts` implementing `CastsAttributes` with a typed `get()` return expose that value object's public properties and methods (value objects in `app/ValueObjects`, `app/Data`), and public methods with one explicit class return type support further chains. Trait aliases, visibility adaptations and `insteadof` choices, nullable unions with one concrete target and supported intersections keep inference; ambiguous unions, DNF types, dynamic casts and arbitrary control flow do not. Documents are bounded to 128 KiB / 8,192 tokens; models use the configured model directories, enums `app/Enums`; navigation opens the owned declaration. No source reads, PHP, database or network access happens during completion.
- In `javascript`, `typescript`, `vue`, `javascriptreact` and `typescriptreact` files, Ziggy route names complete and open in `route('...')` and `route().current('...')`, including `:href="route('...')"` in a Vue template; it works from the in-memory route index only and returns at once without `route(` / `.current(`. Page names are not completed in JavaScript (no Inertia client call takes one). Scanning is line-bounded for quotes and backticks; block comments carry across lines, so a `/*` in a multi-line template literal hides later route calls in the file.
- Also: Pest dataset and group names, Socialite drivers, `pint.json` and `phpstan.neon`, and 26 PHP snippets that add their imports.

## Checks

- Inventory (live, on unsaved text through DiagnosticsProvider against the complete cached inventory; sources over 32 KiB refused, at most 200 findings, nothing while the index is partial — the 3 s reading budget ran out): a view that doesn't exist, a config key missing from an array (or config file) the project defines, a translation key missing from a lang file the project has. Keys built at run time or with a wildcard aren't checked; route names only when _Settings › Plugins › Laravel_ asks for it, because packages add routes the plugin can't see.
- Eloquent (`checkEloquent`, PHP files): `Post::create($request->all())` / `(new Post)->fill($request->all())` when `Post` in `app/Models` or `app/` has `$guarded = []` and no `$fillable`; a literal key of `Post::create([...])` that a non-empty `$fillable` leaves out; `Prunable`/`MassPrunable` without `model:prune` mentioned in `routes/console.php`, `app/Console/Kernel.php` or `bootstrap/app.php` (quiet when none can be read); `orderBy('created_at', 'desc')` (also any literal column ending in `_at`, `_date` or `date`) with a quick fix to `latest()` / `oldest()`. Models with `getFillable()`, `#[Fillable]` or `unguard` stay quiet, as do classes without a project file and dynamic class names.
- Functions (`checkFunctions`): `env-outside-config`, a warning on `env()` calls outside `config/`, `bootstrap/`, `vendor/` and `tests/` (env returns null once configuration is cached).
- Unknown names (warnings, one settings switch each): `<x-name>` with no component file or class; `<livewire:name>` / `@livewire('name')` with no class under `app/Livewire` and no `livewire.name` view; `Inertia::render('Page')`, `inertia('Page')` and `Route::inertia()` naming a page missing from `resources/js/Pages` or `resources/js/pages` (`vue`, `jsx`, `tsx`, `svelte`); `Model::factory()` of a project model without `database/factories/<Model>Factory.php`. Package-namespace names, run-time-built names and providers registering component paths/namespaces (`anonymousComponentPath`, `componentNamespace`) stay quiet. Component checks are off when `composer.json` lists a package shipping un-namespaced components: any `*/blade-*` package (icon packs such as `blade-ui-kit/blade-heroicons`), `laravel/jetstream`, `filament/*` or `livewire/flux`; Livewire checks are off when a provider calls `Livewire::component()`, `componentNamespace()`, `addNamespace()` or `addLocation()`. `Blade::component(Alert::class)` registers `alert`; a call with no literal alias or class makes the check quiet.
- Routes: `laravel.unknown-route-controller` and `laravel.unknown-route-method` (setting `reportUnknownRouteControllers`; namespace from `controllersNamespace`, default `App\Http\Controllers`): a controller imported from the namespace with no file, and a method it doesn't declare. `laravel.missing-resource-methods` (setting `reportMissingResourceMethods`) lists every missing resource method of `Route::resource` / `apiResource`; `only` and `except` are honoured. Quiet for invokables, vendor controllers, traits, `__call`, other parents than `Controller`, and `Route::controller(...)` groups.
- Livewire: `laravel.unknown-livewire-method` (setting `reportUnknownLivewireMethods`): event attributes (`wire:click`, `wire:submit`, `wire:keydown`, …) naming a method the component class of a `livewire/` view doesn't declare. Quiet for classes with a trait, a parent other than `Component`, `__call`, `#[Computed]`, `#[On]` or Volt, and for expressions (`$set`, `form.save`, `a = 1`).
- `where()` values that the column's enum cast lacks (setting `enumValueInspection`), with a quick fix to the closest case; the values complete from the enum.
- Security (`checkSecurity`): request data passed unfiltered to `create()`, `update()` and `fill()` (quick fix to `$request->validated()` when a Form Request is in use), variables in raw SQL, `$guarded = []`, `Model::unguard()` and URIs excluded from CSRF verification.
- Upgrade (`upgradeInspection`): code removed in a Laravel major the project hasn't reached yet, with a rename fix where one exists.
- Translations (`missingTranslationInspection`): keys some locales have and others lack.

Source-reading Eloquent, function, Livewire-method and route-controller checks run on open/save, not through the live provider.

## Quick fixes, intentions and refactoring

- Quick fix (⌥⏎) on a missing `file.key` translation key: add `'key' => 'key'` to the main locale's lang file.
- Validation strings ↔ arrays (`'required|email'` ⇄ `['required', 'email']`; not offered with `regex:` rules, `Rule` objects, closures, embedded `|` or regex values with `,`), also for the whole array at once; `'UserController@index'` → `[UserController::class, 'index']` when the file is in `App\Http\Controllers` or imports the class (no import added), also file-wide; `{{ $x }}` ⇄ `{!! $x !!}` in Blade; `'exists:users,id'`, `'unique:users,email'` (at most two arguments), `'in:a,b'`, `'not_in:a,b'` → `Rule::…` with the `Illuminate\Validation\Rule` import; `Route::`, `Auth::`, `Str::` and the other core facades get their `use` line; Blade `class="btn btn-primary"` → `@class(['btn', 'btn-primary'])` (not offered with `{!! !!}`, `@if`/`@php`, a single quote, an empty value or an existing `@class`).
- `scopeActive()` → `#[Scope] protected function active()` with the import ("Use #[Scope] on all scope methods" for every eligible one); "Move $x to a constructor property" (promoted property, rewrites `$x` to `$this->x`; not offered when reassigned, captured by `compact` or the class extends something other than `Controller`); "Inject … instead of the facade" replaces every use of a core facade with an injected property of the documented underlying class and removes the import; "Extract to translation key" on a selected string adds the entry to the existing main-locale lang file (`messages` first; nothing is created); in a form request's `rules()`, "Add validation rules for the columns of Post" appends missing columns (`'title' => ['required', 'string', 'max:255']`), in a model "Add the missing columns to $fillable" (both need a multi-line or empty array); "Remove IDE helper PHPDoc from model" removes the `@property`/`@method`/`@mixin` lines, and the editor action _Remove IDE helper PHPDoc from indexed models_ covers up to 256 indexed models with one atomic, undoable workspace edit.
- **Create missing literal Blade view**: from a plain first argument of `view(...)` / `\view(...)` or non-overridden `@include`, `@includeIf`, `@extends`, previews one new file under `resources/views` and applies one non-overwriting Create that opens it. Names are at most 128 ASCII bytes in up to 16 dot-separated alphanumeric/underscore/hyphen segments; namespaces, escapes, interpolation, concatenation, heredocs, custom `viewPaths` and non-conventional `config/view.php` are refused, as are targets owned by a separately opened nested project. Sources are limited to 128 KiB, view configuration to 64 KiB; runs no PHP.
- **Extract reviewed HTML/simple-variable Blade view…**: a complete selected HTML element up to 4 KiB in a bounded plain HTML/simple-echo Blade document becomes one non-overwriting Create plus one source Edit atomically; selected `{{ $name }}` reads become `['name' => $name]`, preserving child bytes/CRLF and UTF-16 selection. PHP, directives, comments, components, script/style, computed expressions and custom include directives stay quiet.
- **Create reviewed mapped FormRequest …**: an absolute `\Prefix\Http\Requests\NameRequest` parameter type (or a short type with one exact unaliased `use`) creates the missing PHP file through one exact production Composer PSR-4 mapping (namespace prefixes and source roots up to 8 segments / 256 bytes; `App\` → `app/` and explicit roots like `domain/` supported; overlapping, fallback, dev, case-variant and opaque mappings refused; a source-root scan past 4,096 results refuses the operation, including case-equivalent targets). `authorize()` returns `false`, `rules()` stays empty. No controller imports or source change, no PHP.
- **Promote literal validation to reviewed FormRequest…**: on an explicit `\Illuminate\Http\Request` parameter of a plain controller method whose body is exactly `$request->validate([...])` (or `$validated = $request->validate([...]); return $validated;`), after review creates the request class, transfers the literal rule array, and replaces the call with `validated()`; `authorize()` returns `true`. No PHP runs.
- Typed rename actions exist for proven route, config, translation and explicit Blade-alias literals, and filename-based view/anonymous-component rename uses one reviewed move-and-reference transaction. **Find Literal Source Matches… (Read-only)** scans conventional sources (routes, resources/views, config, lang, src and the current document; 2,048 paths, 8 MiB total, 512 matches, 128 KiB per source) for matching literal spellings and opens results; it adds no Rename anchors.
- **Find Unused Views** lists the views no code names (`view()`, `@include`, `@extends`, `Route::view`, mail and `markdown()` calls); components, `errors.*`, `livewire.*`, `vendor.*`, `mail.*`/`emails.*` and package views are never listed, entries are marked _maybe used_ when the project builds view names at run time, and a literal prefix (`'reports.' . $type`) counts as used.

## Generators

Generator commands ask for names and options in dialogs, then run `php artisan` in a native keyed terminal session (optional `process:php` capability, trusted projects only; on Windows background PHP runs through `php-win` with no console window when `process:php-win` is granted). A matching successful exit refreshes only the currently owned project index; failed, closed, foreign and duplicate completions don't. They are interactive terminal operations, not persisted Run configurations.

- _Run Artisan Command..._ opens the Artisan workspace; _Run Artisan in Terminal…_ keeps the older terminal picker with bundled fallback choices.
- _Generate with artisan make..._: 30 `make:*` generators with their flags (`--resource`, `--api`, `--requests`, `--inline`; Livewire only when installed), plus package/custom `make:*` commands from a captured snapshot.
- _New Eloquent Model..._ (`-m -f -s -c --policy --all`) with independent factory, resource and relation output selections; _Generate for Model..._ (policy, observer, factory, resource or controller with `--model`; right-click a model file in the Project view to skip the model pick). With `project.write` allowed the factory and JSON resource are written with the model's migration columns, otherwise artisan makes the empty stub. Factories map foreign keys ending in `_id` to declared owned factory classes (unknown mappings stay explicit placeholders); resources can include proven relations through `whenLoaded()`, optionally wrapped in an associated declared resource; per-kind directories, namespaces, bases and postfixes flow through the reviewed plan and Composer proofs.
- _Create Missing View, Component or Controller_ (editor context menu, from the name under the caret; also a Job, Mail, Event, Notification, Listener, Policy, Request, Resource… class named by `new X` or `X::class` that no file defines). Nova, Filament and Livewire form generators appear when `composer.json` requires `laravel/nova`, `filament/filament` or `livewire/livewire`. Names are validated before they reach the command line. Generator entry points open the Artisan workspace's captured form when current local metadata matches; opening a form runs no PHP.

The Generators workspace adds model field/relation/index planning with a graphical existing-model editor (reviewed casts and mass-assignment edits), module-local factory/seeder generation, configurable generation classes/postfixes and per-kind destinations. Project custom presets and module mappings use `.openidea/laravel-generators.json` and `.openidea/laravel-templates/`; project/user preset CRUD and private user storage are available. Primary keys include numeric, UUID/ULID and custom strategies with timezone-aware timestamps. **New Laravel Project…** uses installed CLI help to gate options and launches an explicitly reviewed native terminal.

The Models workspace lists source and captured-schema model inventories with reviewed helper PHP, model-from-captured-table drafts, handwritten-PHPDoc-preserving model documentation and new-field/migration actions; cast/accessor/inherited members and proven factory/resource/migration/policy/observer/seeder associations feed the grouped tree. Helper storage/count/date preferences persist per project; **Configure Model Helper Parameters…** saves them after review; **Regenerate Reviewed Model Helpers…** supports reviewed multi-model selection, helper files or preserving/overwriting PHPDoc, proven cast/relation/scope signatures and optional counts.

New file templates: Laravel Controller, Resource Controller, Job, Event, Listener, Mailable, Middleware, Form Request, Policy, Observer, Enum, Seeder, Factory, Migration (anonymous class), Pest Feature and Unit Test, Action, Cast, Global Scope, Notification, Validation Rule, Trait, JSON Resource, Service Provider, View Composer, Exception, Livewire Component, Broadcast Channel, Console Command, Http Exception, PHPUnit Feature and Unit Test, Resource Collection, plain Class, Eloquent Model, Dusk Test, Nova Resource, Livewire Form, Fractal Transformer, Livewire Volt Component, Inertia Vue / React / Svelte Page and Blade View, Layout, Anonymous Component and View Extending a Layout, written from Laravel's documentation and default stubs. The host gives a template only the file name and caret position, so each uses the default namespace of its type with no prompts for a model or table; a migration file name needs its timestamp prefix typed by hand.

## Tool windows

The _Laravel_ tool window hosts the workspaces — _Routes_ (the default), _Views_, _Config_, _Translations_, _Middleware_, _Env_, _Components_, _Artisan_, _Runtime_, _Database_, _Schema_, _Models_, _Generators_, _Processes_ and _External Services_ — each preserving its own search and selection; Reindex is available everywhere, double-click opens the definition, and **Show Laravel Tool Window** brings it forward.

- Routes: the route list shows the endpoint icon, path and grey `[METHOD] Controller` text; *Filter* narrows to one controller, *Flat/Tree* groups by controller; row actions *Copy as curl* and *Create HTTP Request File* (writes `http/<verb>-<path>.http`, needs `project.write`; without it the request is copied). Method names appear in row details; multi-method routes ask which method for cURL/HTTP generation. **Send Request (Executes Project PHP)** opens a Request tab that runs the route through its HTTP kernel without a server: URI parameters, query, JSON body prefilled from Form Request rules or inline validate, Act as user id, Accept JSON and Roll back database changes (on by default; with it off a write needs a second click). The response shows status, time, query count, size, redirect, headers (cookies masked) and body; Copy as cURL copies the same request. With rollback on, nothing is sent unless a transaction really started on the default connection. **Search Routes…** matches names, URIs, methods and controllers with fuzzy ranking; source-verified captured routes also appear in native endpoints discovery. **Refresh Registered Routes (Executes Project PHP)** explicitly runs `php artisan route:list --json --no-interaction --no-ansi` (bounded to 4 MiB, 5,000 routes, four seconds of polling) and captures real URIs, names, methods and controllers including loops, conditional registration and package routes; snapshots stay in memory for up to eight projects and are retired by reindex; failed or cancelled refreshes retain the previous snapshot; the static source index remains the fallback and unresolved dynamic URIs are omitted rather than displayed as `/?`.
- Views: a View / File / Folder / Namespace table with folder and namespace filters, sortable columns and source activation (folder labels follow the physical path below the indexed root; vendor overrides and configured namespaces keep their Laravel namespace). Config: Key, Value and File columns; values are bounded source previews (including `env(...)`, booleans, numbers, null, quoted strings), not evaluated configuration; array nodes stay labelled `array`; indexing traverses list offsets, explicit integer keys and `ClassName::class` keys, supports 64 nesting levels, and marks files with unsupported arrays or reached bounds incomplete (missing-key diagnostics withheld for them; each source limited to 2 MiB and 20,000 entries). Translations: every locale definition in Key, Locale and Value columns with a locale filter; the counter counts locale-specific entries while completion and navigation prefer the configured main locale. Runtime database sources support Connect through the native credential dialog and reviewed removal of connections and saved credentials.
- Database: lists every migration table with its models, columns, indexes and foreign keys; **Compare with database** boots the app and lists pending migrations, tables only in the migrations or only in the database and missing columns and indexes; **Rows** shows a table read-only and paged with secret and personal data columns masked by whole key words. Compare and Rows run read-only PHP through the existing Artisan runner and need no new capability; **Refresh Database Metadata (Executes Project PHP)** captures schema explicitly (four-second polling, 4 MiB, 5,000 rows); connection names are retained in model and migration output, including migration create/drop calls.
- Schema: draws every table with its primary, foreign and unique keys and the model using it, joined by foreign keys (solid) and model relations (dashed), with pan, zoom, Fit, filter and click-to-open migration.
- Components: cached Blade class, anonymous and registered alias components with Livewire classes; template tag, component type and source file with a type filter and sortable columns; class components win over anonymous templates with the same tag; rows exclude sources owned by another open project; browsing never runs PHP.
- Artisan: a searchable command list grouped by namespace (General for unprefixed, up to eight Recent), an arguments/options form with exact PHP argument-vector preview, contextual stdout/stderr and session history. Defaults are shown as hints and left to Artisan when inputs are omitted; required arguments and unsupported optional-argument gaps are validated before launch; repeated values use one entry per line; optional-value flags can be enabled without a value; captured runs use an argument vector without a shell, with `--no-interaction` and `--no-ansi`; opt-in additional options and trailing arguments use quoted argv parsing, with extra options before the structured `--` boundary and trailing data after it. Captured execution uses local `php` or the configured Docker target, one captured run per project, up to 64 KiB stdout / 16 KiB stderr with explicit truncation, a five-minute polling limit (paused while the tab is hidden), and up to 20 history runs bounded to 128 KiB kept in memory. Cancel stops the owned process; successful runs reindex. Use *Run in Terminal* for interactive commands and long-running workers.
- Runtime: explicit snapshots of Application (`about --json`), Events (`event:list --json`), Schedule (`schedule:list --json`) and Failed Jobs (`queue:failed --json`), plus Queue Status, Workers and Logs (one selected owned `storage/logs/*.log` file, at most 64 KiB / 200 lines; queue statistics report unavailable metrics explicitly; worker visibility uses readable Linux `/proc`, other platforms report unavailable). Each capture has a four-second polling / 4 MiB output limit, a 5,000-row bound and owner checks before adoption; failed captures retain previous snapshots; the session cache is bounded to 32 captures / 8 MiB. Nothing runs merely by opening the tab; refresh explicitly after database/environment changes. Failed Jobs lists metadata, not pending counts, payloads or exceptions; Application information uses a fixed allowlist excluding config/environment secret values. **Retry Selected Failed Job** shows a native review and issues a single `queue:retry`; bulk retry is withheld. **Inspect Queue…** accepts a connection/queue override.
- Processes: starts the development server, queue worker and schedule worker in a terminal tab; stop or restart them from the tab.

## Commands, metadata and MCP

Commands under the _Laravel_ category: Reindex Project, Clear All Caches (`optimize:clear`), Clear Application / Config / Route Cache, Clear Compiled Views, Run Migrations, Link Storage, Seed Database, Fresh Migration (drops all tables, asks for a second run within 30 seconds) and Show Route List. They run `php artisan` and all but Show Route List reindex afterwards. Run configurations (`php artisan serve`, `test`, `queue:work`, `schedule:work`) are offered for any project with an `artisan` file. **Search Names…** searches route names, views, components, config, translations and env keys in one list; **Find Unused Views**, **Open Route Declaration**, **Open Error Stack Frame…**, **Open Model Source**, **Run Command From Class…** (source-verified Run markers using captured command metadata) and the recovery/helper-automation commands complete the set. The status bar shows the Laravel version and the PHP version.

**Refresh Artisan Command Metadata (Executes Project PHP)** shows a complete review — verified project/working directory, the literal `php` runner (host PATH), exact argv `["artisan","list","--format=json","--no-interaction","--no-ansi"]` — before anything runs; dismissing the review runs nothing. It needs `process:php`, `project.read` and optional `storage`. Discovery uses a kept process with closed stdin, at most 256 waits within a four-second budget, and rejects output beyond 4 MiB; the accepted snapshot (1–512 commands with unique bounded names and argument/option definitions, up to 128 each; order and bounded defaults preserved; aliases not used to build forms) is cached in schema v2 under a 5 MiB envelope / 4 MiB metadata bound, keyed to the project root, logical `php` runner, argv and fingerprints of `artisan`, `composer.json` and `composer.lock`. Failed, cancelled, stale or malformed refreshes retain the previous snapshot; changed fingerprints make the snapshot unavailable to the picker. Browsing, rendering, providers and typing never execute PHP.

**Docker Artisan metadata** (opt-in): configure `artisanDockerSocket` (a local `unix:///absolute/socket`), a full 64-hex running `artisanDockerContainer` ID and an absolute `artisanDockerWorkdir`. **Refresh Docker Artisan Metadata (Executes Container PHP)** reviews the exact project/CLI directory, endpoint, target, workdir, inspect and exec argv before any Docker process starts; every invocation passes `--host unix:///...` explicitly (no ambient Docker context or DOCKER_HOST). Before exec, fresh inspection must match the full ID, running/unpaused/not-restarting state, image/start identity and exactly one bind mapping this project root to the container directory; overlapping or shadowing mounts are refused. CLI processes share a four-second / 16-wait budget and 4 MiB combined-output bound; accepted metadata is stored under its own bounded 5 MiB envelope with image/start/mount proof and the same `artisan`/Composer fingerprints; failed or stale candidates retain the previous snapshot. **Browse Cached Docker Artisan Metadata (Read-only)** never runs Docker. **Choose Docker Target…** discovers running local containers (Compose/Sail/DDEV candidates from curated labels) and accepts only verified project bind mappings (volume-only, remote and Mutagen-style roots refused); **Use Configured Docker Target** clears the choice. The Artisan PHP runner selector switches between Local PHP and Docker; catalogs, drafts and recent commands stay separate, and each run re-inspects the target.

Seven tools are declared to OpenIDEA's built-in MCP server: `inventory` (paginated cached routes/views/components/models/config key names and related inventories, without config/environment values), `artisan_commands` (captured definitions and revision token; never runs PHP), `runtime_snapshot` (captured section rows and timestamps; raw log tails require explicit `includeLogs: true`), `runtime_refresh` (execute one inspection command), `artisan_execute` (start a captured command with structured values; returns a job), `artisan_job` (poll the owned job and bounded output) and `artisan_cancel`. Mutating tools use the host's MCP confirmation and Restricted Mode policy; project grants still apply and an agent receives no extra permissions. The registered prefix is `aritti_laravel__`, e.g. `aritti_laravel__inventory`.

## How it works

Everything works from a text index of the project; the features needing a full PHP type model are listed under _Not implemented_. Saving a file under `routes/`, `config/`, `lang/`, `resources/views/`, `app/Http/Controllers/` or `app/Mail/`, `.env`, `.env.example`, `bootstrap/app.php`, `app/Http/Kernel.php` or `composer.json` rebuilds the index; scanning has a three-second budget and a 5,000-file discovery cap. Route group handling is textual: a group whose body is a file (`->group(base_path('routes/admin.php'))`) doesn't add its prefix to the routes in that file, and `Route::resource` guesses the singular of a parameter by dropping a trailing `s`. Endpoints compose route-file paths with literal `withRouting` API prefixes (including custom and empty) or literal `RouteServiceProvider` mounts; unsupported dynamic and unmounted API routes are omitted.

View namespaces and extra view roots come from `ide-blade.json` at the project root or `.idea/ide-blade.json` (both read when present): `{"namespaces": [{"namespace": "admin", "path": "modules/admin/views"}]}` indexes those views as `admin::users.index`; a blank or missing `namespace` adds a plain view root, an entry without `path` and malformed JSON are ignored; only these two paths are read. Vite entries, components and Livewire components are indexed with the project (a new file under `resources/js` or `resources/css` shows up after a reindex or the next watched save). Supported `ide.json` roots, custom literal call sites, package overrides, Passport scopes, additional gates/middleware, FQN model/table mappings, declared custom Route facade methods, bounded Wayfinder references, Vite config/manifest sources, consumed helper mixins/constructor forwarding with signature help, route request actions, proven imported/qualified/absolute controller-string conversions and additional rule-object conversions, and Blade component `viewPaths`/`phpNamespaces`/explicit list/`fromConfig` declarations feed the owned inventories and namespaced/bare-tag props consumers. Literal Composer `autoload`/`autoload-dev` PSR-4 roots extend the owned class/trait/cast/value-object/enum inventory.

Cache ownership follows the document's current innermost open project: a nested project cannot inherit an outer app's inventory, unknown/denied ownership withholds cached results without discarding another root's cache, and view configuration inputs or targets owned by a separately opened nested project are refused. Candidate navigation targets are re-read through the project API so unsaved changes update ranges or remove stale links; file-change events refresh cached relationship keys. Navigation computes UTF-16 target widths from the recorded source token (a multiline spelling becomes a point destination), and Blade section/stack completion parses the current target text rather than projecting saved offsets onto a dirty buffer. Model/factory/policy/observer/seeder, migration/table, controller/route and listener/event relationships come from the project-owned navigation model; they are not published as host Rename/Find Usages anchors. Opaque PHP and Blade data (raw PHP blocks, Blade comments, stored `@php`/`@verbatim` blocks, heredocs, ambiguous delimiters) never becomes literal inventory facts, and PHP comments stay trivia in literal adapters.

Hover on a closed-literal route, view, config or translation match shows the cached source location, bounded route/key/locale details and a Laravel documentation link (documents over 128 KiB and names over 512 bytes refused, displayed fields capped at 512 characters). Unqualified helper names or one explicit global prefix (`view(...)` and `\view(...)`) receive Laravel features; explicitly foreign namespaces (`Vendor\view(...)`, `\Vendor\Config::...`) and foreign qualified classes do not. Reindex and saved source changes refresh mounted pages without scanning; the pages never run Artisan, CLI or HTTP work on their own.

Settings: problems on/off, route problems, one switch each for unknown Blade components, Livewire components, Inertia pages and `Model::factory()` without a factory, extra view directories, main locale, public directory. Required capabilities are `project.read` and `events`; optional are `project.write` (native factory/resource creation, Create HTTP Request File), `process:php`, `process:php-win`, `process:docker`, `process:composer`, `process:laravel`, `fs.read:~`, `database.sources`, `secrets`, `net:127.0.0.1`, `net:localhost`, `editor.read`, `clipboard` (Copy Output, Copy as curl) and `storage`; denied capabilities degrade rather than fail loudly.

**Why `fs.read:~` is requested (optional).** `project.read` is enough for everything except one case: a `directoryFiles` source in a project's `ide.json`, which offers the files of a directory as the names for a custom call site's argument. The project API only returns files, so an empty directory can't appear in that list; `host::fs::read_dir` can. That call needs a filesystem grant, and the only scope that covers a project wherever it lives is the user's home directory, so the plugin asks for `fs.read:~` rather than a narrower path it can't know in advance. Enumeration only happens while a `directoryFiles` source is being indexed. Each directory is first checked to be inside the current project (not a symlink, not a nested project's), the walk is bounded (64 listings, 4,096 entries, 31 levels deep), and the plugin never lists, reads or scans other files under the home directory. Only entry names and kinds (file or directory) are read, never file contents. If you deny the grant, nothing breaks: the inventory is built from the project's files as usual, empty directories are left out, and the plugin reports a partial-inventory diagnostic saying the scoped filesystem grant is unavailable. Leave it denied if you don't use `directoryFiles` sources.

## Not implemented

- General dynamic PHP resolution: container types, full Eloquent/facade semantics, imports and alias resolution, runtime registrations, effective runtime configuration and locale — the text index cannot see what a full language model would.
- Framework-wide Rename/Find Usages: navigation relationships are not Rename anchors; `Post`, `PostFactory` and inferred `posts` are not interchangeable spellings.
- Full inline-validation/controller promotion beyond the literal subsets; custom/namespaced view roots in missing-view creation and extraction; complete module resolution.
- Vite-entry freshness without a reindex or watched save; route names from vendor packages; Inertia page names in JavaScript.
- Terminal autocomplete; full Monolog format/timezone coverage and compiled-Blade frame mapping.
