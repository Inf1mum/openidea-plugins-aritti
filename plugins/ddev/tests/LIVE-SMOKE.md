# Optional live DDEV smoke tests

Run only with Docker and DDEV available. This creates a disposable PHP/MariaDB
project, starts containers, executes its fixture commands and deletes that project
in a `finally` block. DDEV may download images and start its shared router.
Image/build caches remain. Existing projects are not stopped/deleted; automatic
cleanup of unrelated obsolete containers is explicitly disabled. Helpers started
by this runner are stopped only if no other DDEV project is running.

Build the plugin first, then run:

```sh
openidea-plugin build plugins/ddev
python3 plugins/ddev/tests/live-smoke.py --xdebug
```

The optional `--xdebug` check briefly opens an ephemeral TCP listener on the host
and uses DDEV's `host.docker.internal` connect-back route. Omit it for the PHP,
Node, Composer, description, Services model, database metadata and SQL checks.
The Cargo host dependencies are substantial; `CARGO_TARGET_DIR` may select an
existing shared cache. The normal test suite never starts containers: the native
live test is ignored by default and the Wasm hook needs `DDEV_LIVE_PROJECT`.

The runner performs three different checks:

1. **Native plugin logic, real DDEV:** the SDK host is mocked, but its finite
   process callback executes real DDEV in the fixture. The port parses actual
   running-project JSON, renders Services data and produces Database metadata.
   Commands generated by the port for PHP/Node/Composer are executed against the
   containers. Empty arguments and literal dollars/backticks survive. Composer
   uses `composer_root: app` and both pre/post-composer hook marker files are
   checked. A real MariaDB `SELECT 1` is executed through `ddev mysql`.
2. **Compiled Wasm registration and real host wrapper:** the existing workflow
   fixture loads `dist/plugin.wasm`. Its registered target is passed to the real
   pinned host's `plugin_target::prepare`, and the resulting PHP/Node processes
   run in the live fixture. Absolute local file paths and `app/sub dir` map into
   `/var/www/html`; literal argv, spaces and empty arguments are checked inside
   the container. The remaining 27-command workflow uses its usual fixture host.
3. **Optional real Xdebug transport:** enable Xdebug in this disposable project,
   accept a real DBGp `init`, verify the container file URI (including `%20`),
   send `run` and check the stopping response and successful debuggee exit.

Observed passing on **2026-11-09** with DDEV **1.25.3**, Docker **29.4.0**,
PHP **8.4**, Node **24** and MariaDB **11.8**, on local macOS/OrbStack. The complete
runner, including its cleanup, was also executed successfully.

This is not a native IDE session: terminal presentation, the secure Database
credential store/native connection UI, IDE breakpoints and adapter integration
remain outside this test. SQL goes through DDEV's database client, not OpenIDEA's
Database source connection. The Xdebug test validates transport/protocol/source
URI, not the IDE's full debugger workflow. Windows/remote behavior is untested.
Generic-target Composer semantics and pre-launch validation still have the
[recorded limitations](../SOURCE-AUDIT.md); the passing Composer check exercises
the port's explicit `ddev composer` command.
