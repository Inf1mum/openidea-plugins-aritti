# Twig

Twig template support for OpenIDEA, which has no Twig grammar of its own. `.twig` files are detected and highlighted with a hand-written lexer: Twig comments, prints and tags (inside HTML attributes too) and the HTML tags and attributes around them. The contents of `verbatim` and `raw` are not read as Twig. MIT; see `LICENSE`.

## Highlighting, structure and folding

Numeric literals (decimal/scientific, digit separators) follow the Twig 3 lexer grammar, so `1..3` is number / range operator / number. Callable members use `function-call`, ordinary members `property`, macro declaration names `function`, and block declaration/closing names `property`. Built-in test names after `is`/`is not`, the `same as`/`divisible by` connectors, the initial `apply` filter and named argument keys inside call-shaped parentheses use the existing highlight categories. UTF-8 identifier bytes stay in whole-name tokens. These are source-shape roles, not resolved types.

The structure view lists blocks, macros and embedded template heads (a literal or identifier embed head becomes a module entry that parents nested blocks). Folds follow the known opener set (including legacy raw/filter/spaceless and apply/cache), with inline block/set exceptions; unknown custom `{% x %}…{% endx %}` pairs are not inferred and stay quiet. Raw/verbatim closers must be exact tags; unterminated raw bodies stay literal through the end of the document.

## Injected languages

Closed, attribute-free `<script>` and `<style>` bodies, complete `{% block javascript %}` and `{% script %}` bodies are exposed as JavaScript/CSS ranges. Comments, Twig expressions/tags, raw/verbatim text, template holes, external/typed scripts, bodies with nested tags or an HTML wrapper, empty and unclosed bodies are excluded. A configured installed embedded language server can serve those ranges; embedded formatting and Rename remain host-owned. This does not add PHP or full template language semantics.

## Completion and snippets

Tags, filters, functions and tests are offered by position (after `{%`, `|`, `is`, or a bare name). In HTML text thirteen snippets expand after typing a prefix: `blk` block, `mcr` macro, `esc` autoescape, `emb` embed, `ext` extends, `for`, `from`, `if`, `imp` import, `inc` include, `sbx` sandbox, `spl` spaceless, `verb` verbatim.

After `{% import 'forms.html.twig' as forms %}`, typing `forms.` lists the macros that template defines (with their arguments); `{% from 'x' import ` lists them too, and `_self` works for the current file. Duplicate declaration names are withheld rather than offering ambiguous owners; structurally malformed external template sources are withheld. Imported macros and current-buffer `_self` macros also offer named argument completion inside calls (Twig 3.15+ named arguments only; a known older installed Twig version in `composer.lock` disables this assistance). Suggestions preserve existing `:`/`=` separators, exclude supplied arguments and use exact current-document ranges.

Outside Symfony projects, filters, functions and tests registered in the project's PHP (`new TwigFilter('x'`, `new TwigFunction('x'`, `new TwigTest('x'`) join the completion lists, and Go to Declaration on them opens the registration (setting `projectExtensions`, default on). Registration candidates are admitted only in PHP code outside strings/comments/backticks/HTML, at supported constructor or attribute boundaries, with a complete literal first argument. Explicit foreign qualified class names are excluded; recognized Twig qualified and legacy `Twig_` constructors/attributes remain. Heredoc/nowdoc files are withheld conservatively. Extensions from `vendor/` are not read; discovery is capped at 1,500 paths / 12 MiB / 3 s.

## Navigation, scopes and template names

Go to Declaration works on `forms.input`, on names imported with `from … import`, on `_self.name`, and on the template name in `extends`, `include`, `embed`, `import`, `from`, `use`, `include()` and `source()`, opening an existing conventional `templates/<name>` file. A template reference requires the literal to be the complete template expression (argument close/comma or a supported tag terminator/modifier); prefixes of concatenations, filters and coalescing expressions, escaped/dynamic/interpolated expressions, and arbitrary suffix matches stay unresolved. A conventional target must be a concrete same-project file; a separately opened nested template project cannot supply an outer project's include/import target. `block('name')` jumps to the block defined by a plain `{% use 'x.twig' %}` target when exactly one used template defines it once (use-with renames, extends, local overrides and duplicates stay quiet).

Imported macros are read from the current unsaved document. `import`/`from` bindings resolve within the current lexical block, macro or embed container, and only after their declaration ends (a later import cannot own an earlier expression). A known block-local binding shadows a template-level binding without leaking into sibling blocks. Embed and macro bodies require an explicit local binding; conditional/control-flow imports, duplicate same-scope aliases, malformed imports, unknown scope-defining custom tags and crossed or unclosed scopes stay quiet. `_self.name` resolves one unique current-text macro declaration without project access. This is declaration navigation, not proof of runtime registration or variable types.

Setting `templateNamespaces` maps `@namespace/name.twig` loader names to project directories for template and macro navigation. In Symfony projects, `twig.yaml` `twig.paths` (literal block mappings; `templateNamespaces` wins) also resolves `@namespace/` template names; `default_path` and main-namespace (`~`) `twig.paths` resolve plain template names; `when@dev/prod/test` blocks and `config/packages/{dev,prod,test}/twig.yaml` add directories, and a namespace mapped to different directories across them is refused. Empty, `0` or `false` namespaces map to the main namespace, and the `- dir` block-list form is accepted (each entry a main-namespace directory). A literal `new \Twig\Lexer($twig, ['tag_block' => [..], 'tag_variable' => [..], 'tag_comment' => [..]])` in the only open project's `src`/`app`/`lib` PHP sets the delimiters when no delimiter setting is given (non-literal or conflicting Lexer configs are ignored). Variables from literal `->render('x.twig', [..])`/`renderView` calls and `#[Template('x.twig')]` with one literal `return [..]` complete in expressions, and Go to Definition jumps to the controller keys.

In a Symfony project (`symfony.lock`, or `symfony/framework-bundle` in `composer.json`) the `aritti.symfony` plugin owns name completion, route, template and translation completion, and configured namespace/path resolution for external macros; this plugin leaves those out there. `_self` navigation and named-argument assistance remain available there.

## Hover

Hover (setting `hover`, independent of diagnostics) supplies the Twig 3 language documentation catalogue for core tag/filter positions and unique current-template macro declarations or `_self.name()` calls, including macro argument text from the current unsaved document (escaped/bounded source, not evaluated values). Comments, HTML, raw/verbatim bodies, strings, member lookalikes, unknown/extra filters, duplicate macros, external/imported macros and framework `path`/`trans` lookalikes stay quiet. Tag/filter hover links to public language documentation and does not establish that the installed Twig version or custom overrides implement it. No project reads, discovery, process or network requests occur.

## Checks

Live current-document inspections (setting `diagnostics`) report block tags without their `{% end… %}` (`unclosed-tag`), `{% end… %}` without an opening tag (`unexpected-end-tag`) and a `{{`, `{%` or `{#` never closed (`unterminated-delimiter`). A stray `}}` is not reported: it is common in inline JavaScript and CSS. Off by default (setting `expressionErrors`): brackets that do not pair inside `{{ }}` and `{% %}` (`unbalanced-bracket`); strings, comments and `verbatim` blocks are skipped. Other expression errors (unknown operators, wrong argument counts) are not detected. Versioned diagnostics admit only Twig-language `.twig` input; disabled, wrong-language and oversized documents return an empty current result.

## Custom delimiters

Settings `tagOpen`/`tagClose`, `variableOpen`/`variableClose` and `commentOpen`/`commentClose` configure the application's Twig lexer syntax. Defaults are `{%`/`%}`, `{{`/`}}` and `{#`/`#}`. Values must be nonempty, 1–16 bytes and contain no whitespace, controls, quotes or backslashes; opening values must be distinct without one being a prefix of another. Invalid settings withhold syntax/reference providers and produce an explicit settings diagnostic.

Lexer tokens, folds, structure, diagnostics, completion/snippets, macro navigation/named arguments, hover, local binding anchors and injected ranges all consume actual source delimiters. Original physical byte/UTF-16 coordinates are preserved even with unequal-width or Unicode delimiters; no normalized copy is used as edit coordinates. Configure the same delimiters in Twig itself. The host's static comment-toggle declaration still uses `{#`/`#}`.

## Commands and rename

**Twig: Toggle Comment** wraps one selected range or the current line, or removes one enclosing Twig comment, using the configured syntax and independently of the host's static comment shortcut. Edits use the current document version, preserve Unicode/CRLF text and reselect the content. Incomplete comments, nested-closer selections, multiple selections and raw/verbatim contexts refuse rather than produce misleading comment markup. Needs optional `editor.read`/`editor.write`.

Setting `staticTemplateReferences` (default on) builds private exact source models: unique macro declarations, matching `endmacro name`, `_self.name`, literal namespace/from imports, local aliases and literal block inheritance retain physical-source identities. The public DocumentIndexer returns no anchors (the host would insert any rename text unchecked), so native Find Usages/Rename is not published; Go to Definition, read-only highlights and occurrence-count lenses use these models instead. Lens actions recheck source snapshots and open **Twig: Review Static Source Occurrences** independently of the caret.

**Preview Rename Static Twig Symbol…** is a reviewed FileAction for local loop bindings/import aliases and admitted macro/block source families. It validates a new non-reserved identifier (letters/digits/underscore, leading letter/underscore, at most 64 UTF-8 bytes), rejects quotes/interpolation, and constructs a virtual rewritten source graph before returning edits; if occurrence identity changes, a name collides, a reference is captured or a binding disconnects, it refuses. The preview lists exact file/line/column replacements and spellings left unchanged outside the admitted scope; cancellation returns no edits. Source text, project ownership, inventory membership and settings are rechecked after review, and the host applies the edit atomically with undo. Optional `project.write` is needed to apply it. The reviewed scope is explicitly static, not all runtime usages: dynamic imports/members, ambiguous/duplicate names, shadowing assignments, malformed/control imports and unsupported trait/embed/namespaced block models are excluded; conventional cross-template resolution remains with Symfony's configured loaders. **Preview Rename Macro Parameter** is a separate reviewed action that refuses shadowed, string, comment and ambiguous cases; macro parameter rename is a separate scope from symbol rename.

## Formatter

The opt-in formatting provider stays off until `formatterEnabled` is set and `formatterPhar` points to an absolute official **Twig-CS-Fixer 4.1.1** PHAR (release tag `4.1.1` on the official project) whose SHA-256 is exactly `4d099a3be74ea41b0c8f1b2a7033c53a77e7d0dfba36725c2bbaaa19453ed2e5`. The adapter calls the PHAR's in-memory `Fixer::fixFile` (the CLI's `fix` writes files); it does not download or install anything. Requires optional `process:php` plus `editor.read`. PHP runs with `-n`, 128 MiB and a two-second limit; no project configuration, application autoload, formatter cache or external file is read or written. Current text is received over stdin and one full-document edit is returned and applied transactionally; active source text, project, settings and all literal HTML/string/Twig tokens are rechecked before returning an edit, and any semantic change is refused. Unicode and CRLF are preserved. It formats standard Twig delimiter/operator/punctuation/macro-argument spacing only; no identifier renaming, template conversion or HTML indentation rewriting. Range and custom-delimiter formatting are unavailable. PHP/tool denial, wrong release bytes, malformed input, stale source or unexpected output returns an error with no edit. The language-definition Prettier/Ruff fallback does not understand Twig.

## Bounds

Highlighting/outline/folding skip documents over 256 KiB; highlight output is capped at 16,384 tokens; structure is suppressed above 4,096 tags and limited to 2,048 symbols/folds. Diagnostics accept at most 128 KiB, 4,096 recognized tags and 16,384 tokens, returning at most 500 findings. Provider input and imported sources are bounded to 128 KiB; declaration/import parsing is suppressed above 4,096 recognized tags. PHP extension discovery and definition checks require same-project concrete source files under `src/`, `app/` or `lib/` (at most 128 KiB each); definition lookup observes at most 16 cached registrations. Typed PHP files-changed notifications process at most 256 events/paths and 100 ms before conservative cache clearing; without the events grant, activation/saved-event fallbacks apply. Review scans at most 64 owned sources / 2 MiB, 128 local import bindings, 16 affected files and 256 spans; the exact preview must fit 15 KiB; each source is at most 64 KiB, parent chains at most 8, and each graph callback caches at most 16 sources / 1 MiB. Exceeding a bound refuses rather than truncating. Malformed inputs use the existing recovery rules; this is not a complete Twig AST, type resolver or injected PHP/HTML/CSS/JavaScript parser.
