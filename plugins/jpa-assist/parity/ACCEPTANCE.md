# JPA Assist desktop acceptance script

Human scenarios for everything MockHost cannot prove. One scenario per user-visible surface; each lists the ledger rows
(`requirements.json`) it gathers evidence for. A passing, non-example receipt (see Reporting) is the evidence a row needs
before it can move from `partial` toward `verified-parity`. `scripts/check-jpa-receipts.py` parses this file: every
table row starting `| AC-nnn |` is a scenario and every `G/S/I/F` id in its second cell is a covered row.

## Setup

| Item | Requirement |
|---|---|
| Host | OpenIDEA desktop, plugin API 1.5 or newer (`engines.openidea = "^1.5"`); record `Help > About` version in the receipt |
| Plugin | `cd plugins/jpa-assist && openidea-plugin build && openidea-plugin link`, then Settings > Plugins > Reload. Hash `dist/plugin.wasm` with `shasum -a 256` for every receipt |
| Capabilities | Grant required (events, project.read, editor.read, storage) and optional (clipboard, process:java, editor.write) unless a scenario says deny |
| Toolchain | JDK 17+ (Spring Boot 3 fixtures), Maven 3.9+, Gradle 8.10+ (no fixture commits a wrapper). JDK 11 for `legacy-javax-hibernate5` (Boot 2.7, `java.version` 11; JDK 17 is enough for editing) |
| Compile env | `source scripts/jpa-compile-env.sh` before `cargo test` runs that use the opt-in `generated_*` compile tests. Optional here: lets you re-compile generated sources with `javac`/`kotlinc` from the same jars |
| Fixtures | Never open a fixture in place. `cp -R plugins/jpa-assist/parity/fixtures/<name> /tmp/jpa-acc/<name> && cd /tmp/jpa-acc/<name> && git init -q && git add -A && git commit -qm base`. Open that copy as the project folder (for `multimodule-gradle` the repository root; open `entities/` or `app/` as its own project only where a scenario says so). `git status`/`git diff` then prove every byte change |
| CRLF variant | In a fresh copy run `find . -name '*.java' -o -name '*.kt' -o -name '*.sql' -o -name '*.xml' -o -name '*.properties' \| xargs perl -pi -e 's/\r?\n/\r\n/'` and commit it as `crlf`. Re-run the GC-6 check there |
| Compile check | After any generating action run `mvn -q -DskipTests compile` (or `gradle compileJava`) in the copy; a compile error is a `fail` unless the scenario says the output is intentionally a draft |

Fixture references are machine-checked: every backticked path starting with `fixtures/` (relative to `plugins/jpa-assist/parity/`) in this file must exist, and `scripts/check-jpa-receipts.py --check-fixtures` fails otherwise. Paths without that prefix (for example `src/main/...` in steps, or scratch files in the copy) are relative to the fixture copy and are not checked. Do not write a `fixtures/` path for a file that does not exist; describe files the tester creates in "Scratch files" instead.
Fixture names are exact: `boot-jpa-java-jakarta` (J), `boot-jpa-kotlin-jakarta` (K), `legacy-javax-hibernate5` (L), `envers-flyway-liquibase` (E), `mapstruct-lombok-dto` (M), `multimodule-gradle` (G). The "Fixture map" section lists what exists. Java packages are `com.example.shop` (J, K), `com.example.library` (L), `com.example.billing` (E), `com.example.crm` (M), `com.example.mm` (G).

### Action invocation

File actions are the editor lightbulb / Code Actions menu entries (cursor on the entity class line unless the scenario says
otherwise) whose titles end with an ellipsis. Commands are in the Command Palette under category `JPA Assist`
(`JPA: ...`) or the menus named in the scenario. Prompts appear in order; "answer" lists the value to give per prompt label.

## Generic checks (GC)

Every scenario marked "mutating" repeats these. Receipt `checks` map: GC-1 `preview_matches`, GC-2 `undo_exact`,
GC-3 `cancel_clean`, GC-4 `stale_refused`, GC-6 `crlf_ok`. Use `n/a` only for read-only scenarios. Put GC-5 and GC-7
results in `observations`.

| GC | Check | How |
|---|---|---|
| GC-1 | Preview matches applied result | Save the preview text shown by the confirm prompt (copy it into an artifact). Confirm. `git diff` of the created or edited file must equal the previewed text byte for byte (new file: its content equals the preview) |
| GC-2 | Undo restores bytes exactly | After applying an edit action press Undo once in the host. `git diff --exit-code` must be empty and `shasum -a 256` of the file equals the pre-action hash. For create-file actions the file must be deletable by Undo or listed in `observations` as a known limit (see Reporting) |
| GC-3 | Cancel at each prompt leaves no change | Run the action once per prompt, pressing Cancel/Esc at prompt N, for N = 1..last (including the final confirm). `git status --porcelain` must be empty each time and no error toast |
| GC-4 | Stale refusal | Run the action to the final confirm but do not confirm; edit and save the target file (add a blank line) in the editor; then confirm. The action must refuse with a stale/changed message and change nothing further. Repeat with the edit made after an earlier prompt |
| GC-5 | Denied grant | Settings > Plugins > JPA Assist: deny the optional capability named by the scenario (`editor.write` for edits, `clipboard` for copy commands, `process:java` for the console), reload. The action is hidden or fails with a clear permission message; nothing is written |
| GC-6 | CRLF variant | Repeat the happy path in the CRLF copy. New lines in edits and created files use the file's line ending (no mixed endings: `grep -c $'\r' file` equals `wc -l`), preview shows no stray `^M` |
| GC-7 | No overwrite | For create-file actions run again with the target present: refused, original bytes intact |
