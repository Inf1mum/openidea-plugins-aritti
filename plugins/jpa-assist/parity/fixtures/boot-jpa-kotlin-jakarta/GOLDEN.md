## Rules with no live emitter (no diagnostic expected anywhere in this project)

These codes exist in `src/checks.rs` but are emitted only by the legacy full-context path (`findings`/`findings_core`, marked `dead_code` outside tests) or by explicit actions, not by `live.rs::diagnostics`: `jpa-kotlin-plugin-missing`, `jpa-redundant-open`, `jpa-redundant-constructor`, `jpa-listener-without-callbacks`, `jpa-relationship-target`, `jpa-repository-id`, `jpa-unknown-attribute-override`, `jpa-unknown-entity-graph`, `jpa-unknown-entity-graph-path`, `jpa-unknown-map-key`, `jpa-unknown-maps-id`, `jpa-unknown-named-query`, `jpa-xml-class-not-persistent`, `jpa-xml-class-unknown`. Several live rules are intentionally conservative: a class is only judged when every annotation is canonical `jakarta|javax.persistence` (or the registered Lombok/Spring names) and no wildcard import hides an owner, so a real project file with extra annotations may stay quiet. The defect files are written to satisfy those gates.
