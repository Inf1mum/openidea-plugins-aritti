# Quarkus Tools

Completion, checks and Dev Mode run configurations for Quarkus in OpenIDEA: `application*.properties`, `application*.yaml|yml`, `META-INF/microprofile-config.properties` and Java sources.
MIT; see `LICENSE`.

The plugin acts only in Quarkus modules, found through literal `io.quarkus` build declarations in the nearest `pom.xml`, `build.gradle` or `build.gradle.kts` up to the project root (a mere mention in a description, comment or unrelated string is quiet). Conventional Gradle catalogue aliases (`alias(libs.plugins.quarkus)`) are detected from exact `io.quarkus` plugin IDs; hyphen/underscore accessors are normalized; malformed TOML, ambiguous normalized aliases and custom catalogue declarations remain unknown. Module proof is cached for at most 30 seconds; cache-only editor requests never refresh it, so a missed event can leave an at-most-30-second stale window before navigation and metadata go quiet until lifecycle discovery proves the module again. Build invalidation is processed first, and explicit build deletions record bounded in-memory tombstones (at most 1,024 tombstones and 64 directory proofs; overflow suppresses proofs until restart). Cached paths are rechecked against the current deepest host project owner, so a nested project's declarations cannot become outer-project facts.

## Completion, hover and inlays

- Key completion: full dotted keys in `.properties`, the next segment under the current parent in YAML. Each item shows the property's type; its documentation gives the description, the default and any deprecation.
- Value completion: enum values, `true`/`false` and log levels.
- Profiles: `%dev.`, `%test.` and `%prod.` are offered at the start of a key; profiled keys (`%dev.quarkus.http.port`, YAML under `"%dev":`) complete and are checked as their base key.
- Named instances: a key like `quarkus.datasource."users".jdbc.url` is completed (type, default, documentation, values) and checked as `quarkus.datasource.jdbc.url`, for the roots the metadata lists as named (datasource, hibernate-orm, flyway, liquibase, mongodb, redis, oidc, oidc-client, mailer and a few more). Map entries such as `quarkus.log.category."io.acme".level` are not checked.
- Project keys: `@ConfigProperty(name, defaultValue)` on fields and parameters, and `@ConfigMapping(prefix)` interfaces (`@WithName`, `@WithParentName`, `@WithDefault`, `namingStrategy`, `Optional<T>`, nested interfaces of the same file). In Java, `@ConfigProperty(name = "` and `@ConfigMapping(prefix = "` complete keys and prefixes.
- Hover on a known config key or literal Java `@ConfigProperty` name shows the declared type, description, default and deprecation/replacement, and labels the winning catalog: project-source declarations, the selected dependency-JAR snapshot (with GAV/scope and a SHA-256 fingerprint), or the bundled fallback (with its packaged dataset versions — not inferred project versions). Unknown, dynamic and conflicting declarations produce no hover.
- Config inlays show the declared type only; configured/runtime values are never displayed. Java inlays show declared ConfigProperty defaults and ConfigMapping defaults/converters. Inputs over 128 KiB or config documents over 512 keys suppress these diagnostics; results are capped at 500 diagnostics and 200 inlays.

Where keys come from: Quarkus 3.40.1's own configuration metadata for about 170 of the most-used `io.quarkus` extensions (86 contribute keys: 2,797 properties) bundled in `data/quarkus-properties.tsv` (regenerate with `python3 -I scripts/gen-metadata.py 3.40.1 data/quarkus-properties.tsv [extra-artifact-id…]`); the MicroProfile Config static metadata; `@ConfigProperty` and `@ConfigMapping` declarations in the project's Java sources; and selected dependency-JAR models (below).

## Checks

Configuration files (each group has a setting):

- `quarkus.checkSyntax`: duplicate keys, lines without a separator, empty values. An empty value is only a hint, for a property whose metadata documents a default (Quarkus treats it as unset).
- `quarkus.checkValues`: values that are not a number, enum constant, log level, duration or memory size; never booleans.
- `quarkus.checkExpressions` (typo check): `${...}` expressions that look like a typo of a key defined in the same file — never in profile files, never for names that could come from other files, the environment or `-D`.
- `quarkus.checkRequired` (off by default): an Info note on a key whose sibling is set while a required key (no default, not `Optional`) is missing from every `application*` file and `.env`. Only 13 such keys exist in the bundled metadata; values from system properties, other config sources or `-D` are invisible to the check.
- Warnings for deprecated keys, and for unknown keys inside a known group of two or more segments (`quarkus.http.portt`). Quoted map keys and keys of extensions that aren't bundled are never flagged. Unknown-key warnings appear only after the whole project index has been read.

Java sources (text only, no type resolution). Java config facts require a literal framework-qualified annotation spelling or one exact matching import (or known same-package spelling) with no same-file shadow; `ConfigMapping` modifiers and naming strategies require their literal SmallRye namespace/enum owner; scalar metadata accepts exact ordinary unescaped string literals (compound names, escapes and text blocks stay unknown, marking the source model incomplete so it cannot authorize absence claims). `Optional<T>` is unwrapped only with a literal `java.util.Optional` owner.

- `quarkus.checkAnnotations` (on): an `@RestClient` injection whose interface, found in the project with `@Path`, lacks `@RegisterRestClient`; `@Scheduled` with a `cron` of other than 6 or 7 fields (quiet when `quarkus.scheduler.cron-type` is set anywhere), a malformed `every` (checked against the documented `Duration.parse` prefix rules), or neither of `cron` and `every` (a nonempty `cron` takes precedence). Values with `{...}` or `${...}` are skipped. `${key}`/`{key}` references in `cron`/`every`/`timeZone`/`delayed` without a default are noted when no config file sets the key.
- `quarkus.checkUnassigned` (off): a `@ConfigProperty(name = "x")` with no `defaultValue`, not `Optional`, whose key no `application*` file, `microprofile-config.properties` or `.env` sets (profiles ignored; quiet for `quarkus.*` keys, bundled keys with a default, and until the whole project is read; system properties, `-D`, other config sources and `@ConfigMapping` members are invisible to it).
- `quarkus.checkHealthMetrics` (on): a class annotated `@Liveness`, `@Readiness` or `@Wellness` that does not implement `HealthCheck`, a top-level `HealthCheck` class with none of them, a `@Gauge` in a bean with a scope other than `@ApplicationScoped`, and a `@Gauge` method returning a string, boolean or void.
- JAX-RS resource checks (literal source; cross-file ones only in inventory-complete modules): `@PathParam`/`@RestPath` names must match a `{x}` or `{x:regex}` variable of the class and method `@Path` (warning), a variable no parameter binds is info, more than one HTTP method annotation on a method warns, `@GET` with an unannotated entity parameter is info, resource methods with the same normalised template, verb and overlapping `@Consumes`/`@Produces` warn, and duplicate literal `@Scheduled` identity values warn; dynamic values stay quiet.
- Qute Java-embedded templates: literal `@Location` values, injected Template fields and `@CheckedTemplate` methods/records warn when the fresh source inventory proves no template file exists; lookup honours default suffixes (`qute.html`, `qute.txt`, `html`, `txt`) and a literal `quarkus.qute.suffixes` (template-path-exclude, profiled, dynamic or YAML values stay quiet).

Quick fixes: Add `@RegisterRestClient` (with its import) to the interface an `@RestClient` injection names (fully qualified at the declaration, preserving imports), implement HealthCheck, add `@Liveness` or `@Readiness`, use `@ApplicationScoped`, Add defaultValue (by the field's type) and Add the key to the nearest existing `application.properties` (re-reading bounded target keys, refusing unsupported spellings or existing keys).

## Navigation

- Go to Definition links a plain config leaf key with its one exact literal Java `@ConfigProperty(name = "…")` injection name, and back. Annotation ownership requires the explicit MicroProfile import with no conflicting import/local type; dynamic, escaped, concatenated, generic-shadowed and unknown names remain quiet. Parent YAML nodes, profiles, named instances, derived `@ConfigMapping` member associations and placeholders are excluded; no anchors are registered for the host's automatic Rename. Source facts live 120 seconds; bounds are 128 KiB input, 64 Java types, 128 bracket nesting, 512 declarations per file, 512 cached files and 4,096 candidate records per lookup; duplicate targets yield no result.
- Go to Definition on the exact unescaped `@Location("pages/home.html")` value of a non-static, source-proved Quarkus `Template` field opens that exact known template file. Only explicit portable ASCII `.html`/`.txt` paths below conventional `src/main/resources/templates` are linked — no suffix guessing, fragments, custom roots, implicit field naming or CheckedTemplate lookup. At most 256 template paths and 16 module inventories are warmed by events; inventories expire after 30 seconds; provider requests perform no file discovery or reads.
- Java source lenses/document symbols expose exact literal JAX-RS mappings and scheduler triggers; the lens action opens revalidated read-only declaration evidence, including the effective path composed from literal `quarkus.http.root-path`, a single literal `@ApplicationPath` (which replaces `quarkus.rest.path`) or `quarkus.rest.path`, and class/method `@Path` — quiet when ambiguous or non-literal.

## Dev Mode run configurations

`mvn quarkus:dev`, `gradle quarkusDev` and `quarkus dev`. They need the matching binary on `PATH` and are offered only once the matching `process:` capability is granted; a detector can only match marker files by name, so they show in every Maven or Gradle project once granted, Quarkus or not. `./mvnw` and `./gradlew` can't be run (a `process:` program must be on `PATH` or absolute).

## Offline starter and code.quarkus.io

**Quarkus: Open code.quarkus.io** opens the official project generator in the browser.

**Quarkus: Prepare Offline Maven/Qute Starter…** (optional `editor.read`), run from a Java or XML file of the parent project, asks for groupId, a portable lowercase artifact/folder name, project version and an explicit Quarkus 3 platform version (the plugin does not fetch or resolve it). The preview shows every destination and exact UTF-8 content for four files: `pom.xml`, `src/main/resources/application.properties`, `src/main/resources/templates/hello.txt` and a scope/provenance README. Preparation does not write. Within five minutes, **Create Reviewed Quarkus/Qute Starter…** re-previews and returns four atomic non-overwriting Create operations, opening the new POM; existing destinations, open unsaved targets, changed source/version/owner and expired or replayed plans are refused. It only creates a vacant direct child of the existing project, with no merge, source edit, wrapper, build, process or HTTP request. After applying, **Quarkus: Open Reviewed Starter…** checks all four files and asks to open the folder through the ordinary project trust/open flow. This is a small offline Qute scaffold (platform BOM, Quarkus Maven plugin, direct `quarkus-qute` dependency, literal text template): no Java sources, REST endpoint or tests; version availability, JDK compatibility, dependency resolution and remote registry workflows are not verified by it.

## Qute support

- Within fresh known conventional Qute template modules, static include tags navigate to uniquely owned cached template files and offer cached include paths; section snippets complete in HTML/plaintext templates without replacing the host language; source-fact Info notes identify static includes absent from a complete known inventory while acknowledging custom runtime locators. Java implicit injected Template fields and supported `@CheckedTemplate` method declarations link to exact templates; ambiguous variants, overloads, dynamic paths and custom naming strategies stay unknown. `{name}` completion in a template offers literal checked-method parameters, record components, `.data("name", ..)` chains and literal `@TemplateData`/`@TemplateExtension` namespaces.
- **Create empty Qute template**: offered on a Java field with an explicitly imported or fully qualified `io.quarkus.qute.Template` type and an `io.quarkus.qute.Location` annotation containing one unescaped explicit relative `.html` or `.txt` string. Only conventional module `src/main/resources/templates` targets; static fields, ambiguous/shadowed names, dynamic expressions and extensionless names stay quiet. The preview shows the exact target and content (empty, zero bytes), rechecks source, project, build text, target collision and parents, and returns one host-managed non-overwriting Create with Undo.
- Optional typed Qute language server: the [Qute/JDT adapter setup](adapters/README.md) supplies a broker for the official Qute Language Server and Eclipse JDT LS with the official Qute/MicroProfile JDT extensions — hash-pinned profiles, isolated per-session Java workspaces and exact native project settings. Only the exact `.qute.html` suffix is contributed automatically (HTML mode and grammar); generic HTML and Java are not reassigned. The optional JDT configuration overlay also adds saved and unsaved `application.yaml|yml`, `.env` and `config/application.properties|yaml` files as sources (bounded, inside the project root, no symlink escapes; YAML flattened with dotted keys, `[n]` list indexes, quoted keys and `%profile` top-level keys; anchors, flow, block scalars, tabs and multi-document refused).

## Config models from dependency JARs

**Quarkus: Read Config Model from Selected Maven Dependency JAR…** lists supported literal direct dependencies of the current project's root `pom.xml`, reviews the exact project/POM, GAV, declared scope and standard Maven-cache archive, then reads bytes (requires the optional `fs.read:~/.m2/repository`; no Maven/Gradle/Java execution, cache scan, network or extraction). Only the modern `META-INF/quarkus-config-doc/quarkus-config-model.json` layout is supported: plain property names with declared types, scalar defaults, deprecation replacements and static enum hints; optional javadoc descriptions joined by exact `sourceType.sourceElementName`. `quarkus-extension.properties` deployment coordinates, `quarkus-config-roots.list` and older javadoc layouts are deliberately not converted into a catalog. Conflicting names and unsupported structures fail without installing a partial replacement. The snapshot feeds completion, hover, diagnostics and inlays after project-source metadata and before bundled fallback, and is retained ten minutes per project (up to eight exact project roots, session-only, invalidated by matching POM events). Maven scope is narrow: root direct literal GAVs, JAR type, compile/runtime/provided/test scope, no classifier; BOMs, property resolution, Gradle and transitives remain gaps. POMs must be complete supported XML (256 KiB, 4,096 elements, nesting 32, 128 dependencies) with coherent namespaces; archives are classic ZIP bounded at 8 MiB, 2,048 entries, 512 KiB per metadata entry and 100:1 expansion; encryption, ZIP64 and path tricks are refused.

**Quarkus: Inspect Source Declaration** inspects the current source declaration.

## How it works

Current-text diagnostics, metadata hover and type inlays use API 1.3 on the current unsaved document; activation and optional file events warm module, source/config and `.env` facts outside editor callbacks. Diagnostics, hover and inlays do not discover files, read `.env` or contact a server; the optional `events` permission is needed for unknown-key, unassigned/required-key and REST-client absence checks (which also require complete, usable caches), while local value/syntax/annotation checks work on established bundled/current-text facts without it. Oversized cached source/config files mark absence facts incomplete; a denied or cold context stays quiet. Capabilities: required `project.read`; optional `events`, `fs.read:~/.m2/repository`, `editor.read`. Metadata and annotation parsing remain textual rather than compiler or classpath resolution.

## Not implemented

- Converters, runtime config sources, full dependency metadata, effective injected values, converter/default-value hints and Java converter evaluation.
- The remaining Java-side MicroProfile/Quarkus language-server features (code lens beyond literal mappings, broader Java definition/diagnostics, JAX-RS symbols), the in-IDE project wizard (use code.quarkus.io), debugger auto-attach to Dev Mode and the run dashboard, and keys from extensions outside the bundled and selected set.
- Scoped usages/Rename and `@ConfigMapping`/profile gutter associations; `ConfigMapping` navigation beyond same-file groups; nonstandard/generated/test layouts; complete Qute type/member resolution and template Rename; prefixed Maven element layouts and Gradle beyond literal declarations; effective classpath, inherited profiles and runtime models.
