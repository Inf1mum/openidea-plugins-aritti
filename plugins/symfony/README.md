# Symfony

Symfony support for PHP, Twig, YAML and XML files in OpenIDEA, from the project's own sources. MIT; see `LICENSE`.

A project counts as Symfony when it has `symfony.lock` or requires `symfony/framework-bundle` or `symfony/symfony` in `composer.json`. Twig files need the `aritti.twig` plugin (the IDE has no Twig language). One shared UI-kit window holds the Symfony, Profiler and Twig Namespace Paths tabs; commands select their corresponding tab.

## Completion and go to definition (⌘B)

| Names        | Indexed from                                                                                                       | Referenced in                                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Routes       | `#[Route]` / `@Route` in `src/**/*Controller.php`, `config/routes*` YAML/XML, compiled `var/cache/dev/url_generating_routes.php` | PHP `generateUrl`, `redirectToRoute`, `->generate`; Twig `path()`, `url()`                                                                                     |
| Templates    | `templates/**/*.twig` (`templates/bundles/XBundle/` as `@X/`; `twig: paths:` of `config/packages/twig.yaml` as `@namespace/`)                                                       | PHP `render*`, `stream`, `htmlTemplate`, `textTemplate`, `#[Template]`; Twig `extends`, `include`, `embed`, `import`, `from`, `use`, `include()`, `source()` |
| Blocks       | the parent templates (`extends` chain)                                                                              | Twig `{% block name %}`, `block('name')`                                                                                                                       |
| Variables    | keys of the array passed to `render()` by controllers                                                              | Twig expressions (completion only)                                                                                                                             |
| Services     | `services:` in `config/**` YAML, `<service>` in XML, compiled `var/cache/dev/App_KernelDevDebugContainer.xml`      | PHP `$container->get/has`, `service()`, `ref()`; YAML `'@id'`, `'@?id'`; XML `type="service" id=`, `alias=`, `parent=`                                          |
| Classes      | `composer.json` PSR-4 autoload directories                                                                         | YAML service keys, `class:`, `parent:`; XML `class=`                                                                                                           |
| Translations | `translations/**` YAML (nested keys joined with `.`) and XLIFF, by domain                                          | PHP `->trans`, `t()`, `new TranslatableMessage`; Twig `'key'|trans`; domain from the call, `{% trans_default_domain %}`, else `messages`                       |
| Assets       | files under `public/`                                                                                              | Twig `asset()`; PHP `->getUrl()`                                                                                                                               |
| Entries      | `webpack.config.js` `addEntry`/`addStyleEntry`, `importmap.php`                                                    | Twig `encore_entry_link_tags()`, `encore_entry_script_tags()`, `importmap()`                                                                                    |
| Roles        | `ROLE_*` in security config and controllers, plus built-in attributes (`IS_AUTHENTICATED_*`, `PUBLIC_ACCESS`, …)  | PHP `isGranted`, `denyAccessUnlessGranted`, `#[IsGranted]`; Twig `is_granted()`                                                                                |
| Tags         | Symfony's built-in service tags plus the tags used in `config/**` YAML and XML service files                      | YAML `tags:` of a service (`- { name: x }`, `- name: x`, `['x']`, `- x`); XML `<tag name="">` (completion only)                                              |

Translation completion and lookup never fall back to another domain's catalogue when the requested domain has no indexed names. The host-index association graph for event listeners, Twig macros, voters, constraints, transformed class/template names and related gutter links is gated: its global equality keys and synthetic anchors were navigation associations, not proven complete Rename symbols. Explicit Go to Definition from the table above and source-derived tool-window navigation remain; graph-only related gutter links and automatic usages/Rename are unavailable.

## Twig names and structure

In `.twig` files: completion of tag names (`if`, `for`, `block`, `extends`, … and their `end…` forms) after `{%`, filters after `|`, functions in expressions and tests after `is` / `is not`, from static lists taken from Twig's public documentation plus the filters, functions and tests of the project's own Twig extensions (`getFilters()` and friends, `#[AsTwigFilter]`, `#[AsTwigFunction]`, `#[AsTwigTest]`, read from the document index; extensions in `vendor/` are not read). After `alias.` of `{% import 'tpl' as alias %}` (or `_self`) the macros of that template are offered. Template paths after `extends`, `include`, `embed`, `import`, `from` and `use` come from the cached `templates/` index. Names starting with `@` are never reported missing.

## Checks

Files are checked when opened or saved; _Settings › Plugins › Symfony_ turns the checks off. Text inspections are silent when the class, service or file they need is not in the index, and when a name is dynamic or comes from a library. Source-local rules (Twig syntax, YAML scalar, command, practice, deprecation and Doctrine/QueryBuilder checks, PHP route-class, asset, domain and form-alias checks, Twig cached checks, XML duplicate/factory/unknown-parameter and service-class checks) run on the current editor text — up to 32 KiB, at most 200 findings, unsaved changes included — and need an already recognized cached project; cross-file checks read project sources on open/save. Each group has its own setting.

- Problems: missing template, missing translation key (in a domain that has keys), missing route (once the compiled routes exist), missing service (once the compiled container exists), route defined twice in a file, service id defined twice in an XML file, unquoted YAML values starting with `@` or `%` in `config/` and `translations/` (Symfony's parser rejects them), Twig block tags never closed (reported by the `aritti.twig` plugin in Symfony projects).
- _Route controllers_ (`controllerChecks`): `controller-method-missing`, a route in `config/routes*` (YAML/XML) naming `Class::method` where the project class has no such public method, an invokable class without `__invoke`, or a class-level `#[Route]` with neither `__invoke` nor routed methods; `deprecated-route-setting`, only these: the `Bundle:Controller:action` notation (removed in 4.0), `pattern` (removed in 3.0), `type: annotation` on imports (deprecated in 6.4; only reported when composer.json requires `symfony/framework-bundle` 6.4 or newer), and the `_method` / `_scheme` requirements (removed in 3.0; in XML, only in unprefixed routes/route/requirement structures). Classes extending a class other than `AbstractController`, using traits or defining `__call` are not reported.
- _Services_ (`serviceChecks`, YAML/XML under `config/`): `deprecated-service-class`, a `class:` naming a project class with `@deprecated` or `#[Deprecated]`; `duplicate-parameter-key`, one parameter twice in a file; `named-argument-missing`, a `$name` argument the class constructor has no parameter for (not for variadic constructors, services with `parent` or a factory, `calls`, or classes without a constructor; services with `constructor`, `parent` or a factory are not checked for named arguments); `deprecated-factory-setting`, `factory_class` / `factory_method` / `factory_service` (YAML) or `factory-class` / `factory-method` / `factory-service` (XML) on a service, removed in Symfony 3.0, use `factory`; `unknown-parameter`, a `%name%` in `config/` YAML or XML that neither the config files nor the compiled container define (silent without a compiled container, for `%env(…)%`, `kernel.*`, `%%` and any other name shape); `service-class-missing`, a `class:` in one of the project's PSR-4 namespaces without a file (`Tests` namespaces skipped; complete index and strict literal production PSR-4 mappings required; advisory cached absence, runtime autoloading unverified).
- _PHP calls_ (`phpCallChecks`): `form-type-string`, `$builder->add('f', 'text')` with a core type alias removed in Symfony 3 (needs cached Composer evidence for Symfony 2.8 or newer); `missing-asset`, `->getUrl('x')` / `asset('x')` of a file absent from the public directory (not for URLs, absolute paths, dynamic names or a second package argument; assets under `build/`, `bundles/`, `assets/` and directories with no indexed file are not reported; `->getUrl()` is only checked in files that mention `Packages` or `Symfony\Component\Asset`); `missing-translation-domain`, a domain that has no file in `translations/` (only lower-case project-style domain names such as `messages`, `validators`, `security` are reported; dotted or capitalised names such as `EasyAdminBundle` never are); `deprecated-class-usage`, `new X` / `X::class` of a project class marked `@deprecated`, from a file that is not itself deprecated. Class files are read at most once per run (256 KB and 500 files caps); beyond that the checks stay silent. A parent named `Controller` / `AbstractController` counts only when it resolves to the framework's. A PHP scalar-literal argument requires exactly one quoted literal with an unescaped final closing quote; concatenation, ternaries/coalescing and adjacent literals are refused.
- _Twig_ (`twigChecks`): `twig-missing-route`, `path('x')` / `url('x')` of a route absent from the compiled routes (silent without them, for `_`-prefixed routes and dynamic names); `twig-missing-asset`, with the same exceptions as in PHP (named asset packages are refused against the default public index); `twig-route-compare`, a literal compared with `app.current_route` or `app.request.attributes.get('_route')` (`==`, `!=`, `is same as`, `in [...]`) that is not a compiled route; `twig-missing-translation-domain`; `twig-assets-tag-missing` (`{% javascripts %}` / `{% stylesheets %}` literals); `twig-enum-class`, `enum()` / `enum_cases()` naming a missing project class or one that is no enum; `twig-content-outside-block` (error; text or `{{ }}` outside blocks in a template whose first tag is a literal `{% extends %}`; `set`, `import`, `use`, `macro` and tags in general stay legal); `twig-path-replacement` (hint with a quick fix, `href="/blog"` / `action="/blog"` equal to the path of one YAML or XML route without placeholders). Template absence needs an observed bounded scan, unambiguous known paths and a static plain relative literal (concat/interpolation/unknown aliases are quiet); key absence needs a known static domain (Info severity, locale/runtime caveats); static ignore-missing targets can still report source-file absence. They run on `.twig` files from their extension, so they work without the `aritti.twig` plugin. Comments and `{% verbatim %}` bodies are skipped.
- _Twig syntax_ (`twigSyntaxChecks`): `twig-for-condition` (warning; the `if` condition of `{% for %}`, deprecated in Twig 2.10, removed in 3.0, use `|filter`); `twig-component-block-syntax` (error), a `{% block %}` inside a `<twig:Name>` element; `twig-component-self-import` (error), `_self` as the source of `{% from %}` / `{% import %}` inside a component. An unbalanced `<twig:...>` file is left alone.
- _YAML syntax_ (`yamlSyntaxChecks`, files under `config/` and `translations/`): `unquoted-yaml-scalar` (also a value starting with a backtick, or with `|` or `>` that is no block scalar header); `yaml-unescaped-backslash` (hint), a backslash in a double-quoted string that starts no escape; `yaml-unquoted-colon` (hint), a `: ` inside an unquoted value.
- _Commands_ (`commandChecks`): `command-invokable-return-type` (hint), the `__invoke()` of a class with `#[AsCommand]` (the attribute must resolve to the Symfony class) has no `int` or `never` return type; `console-input-mode` (warning), two base modes ORed in the mode of `InputArgument` (`REQUIRED`, `OPTIONAL`) or `InputOption` (`VALUE_NONE`, `VALUE_REQUIRED`, `VALUE_OPTIONAL`), through `new` or `addArgument()` / `addOption()`; deprecated in Symfony 8.1. Modifiers, numbers and variables are ignored.
- _Deprecations_ (`deprecationChecks`, PHP, each gated on `composer.json` requiring `symfony/framework-bundle` at the given version or newer): `filesystem-mirror-copy-on-windows` (8.1, the `copy_on_windows` option of `->mirror()` in a file mentioning `Symfony\Component\Filesystem`, use `follow_symlinks`); `tagged-collection-default-method` (8.1, `defaultIndexMethod:` / `defaultPriorityMethod:` with a string value on `TaggedIterator`, `TaggedLocator`, `AutowireIterator` or `AutowireLocator`, use `#[AsTaggedItem]`); `from-callable-option` (8.1, `alias`, `parent`, `synthetic`, `file`, `arguments`, `properties`, `configurator` or `calls` next to `from_callable` in one PHP-array service; YAML is not checked); `http-kernel-event-argument` (4.3, `GetResponseEvent` family); `controller-get-doctrine` (5.4); `command-default-name` (6.1); `security-class-moved`, `request-get-content-type`, `first-class-callable` (`[$this, 'method']` of an own method), `render-form`, `form-create-view` (6.2); `route-attribute-namespace` (6.4, `Routing\Annotation\Route`, with a quick fix to `Routing\Attribute\Route`); `constraint-array-options` (7.4, `new NotBlank(['message' => …])` and the attribute form). Version gates use strict literal production `require` evidence from bounded valid JSON (a single numeric, caret, tilde, `>=` or trailing-wildcard requirement gives an advisory lower bound; unions, upper bounds, branches, stability modifiers, unsupported constraints and require-dev-only metadata stay quiet) and findings state that the installed/runtime version is unknown.
- _Doctrine_ (`doctrineChecks`, PHP attributes, `*.orm.xml`, `*.orm.yml|yaml`; written from the Doctrine ORM documentation; PHP files count only when they import `Doctrine\ORM\Mapping` or a member of it, aliases followed): `orm-empty-table` (hint), `#[Table]` with no arguments or `name: ''`; `orm-table-deprecated-property` (warning), `indexes:` or `uniqueConstraints:` in `#[Table(...)]` (deprecated since ORM 3.2, use `#[Index]` / `#[UniqueConstraint]`); `orm-lifecycle-callbacks-missing` (warning), a lifecycle attribute (`PrePersist`, `PostPersist`, `PreUpdate`, `PostUpdate`, `PreRemove`, `PostRemove`, `PostLoad`, `PreFlush`) in an `#[Entity]` class without `#[HasLifecycleCallbacks]` (a `#[MappedSuperclass]` is skipped: a subclass may carry it); `orm-one-to-many-mapped-by` (warning), `#[OneToMany]` without `mappedBy` and without a `#[JoinTable]` on the property; `orm-inverse-side-join-column` (hint), `#[JoinColumn]` next to `#[OneToOne(mappedBy: ...)]`; `orm-join-column-nullable` (hint), an explicit `nullable: true` (the default) on a join column in PHP, XML (`<join-column>`) or YAML (`joinColumn` / `joinColumns`); `orm-lifecycle-method-visibility`, a lifecycle callback that is not public; `orm-discriminator-map-duplicate` (PHP attribute and XML); `orm-query-iterate`, `orm-entity-manager-merge`, `orm-flush-entity` (removed in ORM 3, on conventionally named entity managers in files that import one); `orm-column-deprecated-type` (`array`, `object`); `collections-criteria-ordering` (hint, string orderings of `Criteria`). QueryBuilder checks run in files that import a Doctrine query builder or call `createQueryBuilder(`, with a `createQueryBuilder()` chain receiver or `$qb` / `$queryBuilder` / `$builder`: `query-builder-add`, `query-builder-array`, `query-builder-set-parameters` (hints), `query-builder-alias` (`from()` without alias), `query-builder-sort-direction`, `query-builder-time-parameter` (`'CURRENT_DATE'` bound as a parameter) and, with a DBAL import, `query-builder-parts` / `query-builder-execute` (deprecated in DBAL 3.1).
- _Service wiring_ (`serviceChecks`, `src/wiring.rs`; a small class model — constructor parameters, parent, interfaces, resolved through `use`): `service-argument-count` (more positional arguments than the constructor has parameters); `service-argument-type` (a `@service` whose project class cannot be the typed project class or interface); `service-tag-interface` (`kernel.event_subscriber`, `twig.extension`, `form.type`, `validator.constraint_validator`, `security.voter`, `kernel.cache_warmer`, `doctrine.event_subscriber` on a class that lacks the interface); `listener-method-missing` (`kernel.event_listener` with a `method` the class lacks); `yaml-php-const-missing` (`!php/const` of a project class without that constant). Silent when a parent or interface is outside the project and could matter, for traits, `__call`, `parent`, factories, decorators, aliases, named or nested arguments. PHP service files (`$services->set(Foo::class)->args([service(Bar::class)])->tag('x')`) get the argument and tag checks, `type="constant"` XML values get the constant check, and `autowire-wrong-class` compares `#[Autowire(service: 'id')]` with the parameter type.
- _Practices_ (`practiceChecks`, PHP, hints unless noted; roles come from the parent class, interfaces or class attributes): `controller-container-get`, `controller-superglobal`, `controller-debug-call`, `controller-base-class` (the removed `Controller` base class); `constructor-container-injection`; `twig-extension-get-name`; `twig-legacy-class` (warning, `Twig_Foo` names); `form-type-removed-method` and `form-removed-option` (warnings, the Symfony 3.0 form removals); `constructor-request-injection`, `constructor-session-injection`, `constructor-token-injection`, `constructor-user-injection` (request-scoped values in the constructor of a controller, command, subscriber, voter, form type, Twig extension or attribute-registered service); `deprecated-injection` (warning; removed Symfony and Doctrine Persistence types such as `UserPasswordEncoderInterface`, `EngineInterface`); `kernel-project-dir` (a `KernelInterface` used only for `getProjectDir()`); `twig-extension-heavy-constructor` and `command-heavy-constructor`; `request-stack-in-action`; `controller-shortcut` (`new RedirectResponse`, `JsonResponse`, `BinaryFileResponse`); `controller-missing-exit` (warning, `$this->createNotFoundException()` or `render()` as a statement without `throw` / `return`); `bundle-register-commands`; `command-return-value` (warning, bare `return;`, `null`, booleans or strings from `execute()` / `__invoke()` of a `Command`); `request-bag-write` (`$request->attributes = …` on a parameter typed `Request`); `violations-find-by-codes` (literal code); `form-type-instance` (warning, `->add('f', new TextType())`).

Quick fixes (⌥⏎): on a missing translation key, add it to one of the domain's YAML files (existing parsed key paths count, even when the value is empty/null or a nested branch); on an unquoted `@` / `%` YAML value, quote it; on an unescaped backslash in a double-quoted YAML string, double it; on a missing route, template, translation key or domain, change it to the one known name that differs by a typo (a unique candidate within one or two edits). Quick fixes follow the check settings.

Gutter: controller `render()` → template; template → controllers rendering it; `{% block %}` → the parent block it overrides; PHP class → its service definition; YAML service → its class file.

## Code actions

Refactorings in the code actions menu (⌥⏎). Each edits the open file only, and is not offered when a needed import would clash with another class of the same short name.

- _Add #[Route] attribute_: caret in a public, non-static, non-magic method without `#[Route]` of a class named `*Controller` or extending `AbstractController` / `Controller`, with `symfony/framework-bundle` 6.2 or newer. Path and name come from the class and method names (`/blog/show-post`, `app_blog_show_post`); the caret is not moved to the path.
- _Add parameter: Request $request_ / _UserInterface $user_: in a public route action (`#[Route]`, `@Route`, or `__invoke` of a class with a `#[Route]`). In the `__invoke` of an `#[AsCommand]` class: `InputInterface`, `OutputInterface`, `Cursor`, `SymfonyStyle`, `Application`. One action per type (no chooser); a type already in the signature, by short or full name, is not offered.
- _Use TextType::class_: on the second argument of `->add('field', 'text')` when it is a pre-3.0 form type alias; _Use class constants for all form types in this file_ when the file has two or more.
- _Override block "name"_: with the caret on `{% extends %}`, one action per parent block the file does not define; appends a block calling `parent()` at the end of the file.
- _Use Product::class_: a Doctrine `'App:Product'` alias in `getRepository()`, `find()`, `getReference()` or `getClassMetadata()` whose `App\Entity\Product` is a project class.
- _Convert to invokable command_: a class with `#[AsCommand]` extending `Command`, with `execute(InputInterface $input, OutputInterface $output): int` and a `configure()` of only `addArgument()` / `addOption()` calls (modes `REQUIRED` / `OPTIONAL`, `VALUE_NONE` / `VALUE_REQUIRED`). `extends` and `configure()` go, `execute` becomes `__invoke` with `#[Argument]` / `#[Option]` parameters, a lone `parent::__construct();` goes. Not offered for anything else (`setName`, defaults, lifecycle methods, `$this` use of inherited members). Needs Symfony 7.3.
- _Convert Twig extension methods to attributes_: `getFilters()`, `getFunctions()` and `getTests()` holding only `new TwigFilter('x', [$this, 'method'])` entries become `#[AsTwigFilter('x')]` (and `AsTwigFunction`, `AsTwigTest`) on the methods. Not offered with options, other callables or other extension methods. Needs Twig 3.21.
- _Move $logger to the constructor_: caret on a typed, uninitialised class-typed property without attributes; becomes a promoted parameter of the existing constructor (not offered when it assigns the property) or of a new one.
- _Extract translation_: with plain text selected in a Twig template, replaces it with `{{ 'blog.index.read_more'|trans }}` and appends the key to the domain's YAML translation file (`{% trans_default_domain %}`, else `messages`; `.en.` file first). Extraction follows the same known default-domain guard as reference operations: omitted defaults and one literal prefix directive are supported; dynamic, scoped or duplicate defaults never select `messages`.
- _Add form fields for Product_: in a form type whose `configureOptions()` sets `data_class`, appends `$builder->add('field', Type::class);` for the entity properties the form lacks (`#[ORM\Column]` types or typed properties; ids and associations skipped).

## Attribute arguments

Completion inside `#[Route(`, `#[Template(`, `#[IsGranted(`, `#[AsCommand(`, `#[AsEventListener(` and the Doctrine mapping attributes (`#[ORM\Column(` …, aliases followed) offers the argument names, and the values of `methods:`, `schemes:`, `type:`, `fetch:`, `cascade:`, `strategy:` and `onDelete:`. Invoke it by hand; the IDE does not pop it up by itself there. `IsGranted(attribute:)` offers the common role names and `AsEventListener(event:)` the core kernel and console event names. A constraint argument such as `message: 'post.title.blank'` whose text looks like a key (a dot, no spaces) is a `validators` translation reference: completion, go to definition and the missing-key problem.

## Twig variables, types and forms

Completion of variables in Twig also offers what the template defines itself (`{% set %}`, `{% for %}` with `loop`, macro arguments, `{% with %}`, `{# @var name Type #}`; blocks, macros, loops and `with` have their own scope), what other templates pass with `{% include 'x' with {…} %}` / `include()`, the `twig: globals:` of `config/packages/twig.yaml`, `app`, `_self` and `_context`.

After `variable.` in Twig and `$variable->` / `$this->property->` in PHP, members are completed for variables whose class the project sources state: in Twig a `{# @var name Class #}` comment or what a controller passes to `render()`; in PHP a typed parameter or promoted property, `new Class`, `$repository->find()` / `findOneBy()` (the entity comes from `@extends ServiceEntityRepository<Entity>` or `parent::__construct($registry, Entity::class)`), `$em->find(Entity::class, …)`, `getRepository(Entity::class)->find()` and `$container->get(Class::class)`. Twig offers what `object.name` can read (public properties, public no-argument methods, and `getX`/`isX`/`hasX`/`canX` as `x`), following `post.author.` through return and property types and project parent classes. Matching is textual and bounded: a reassigned or unknown value, a union type or a library class (`vendor/` is not read) has no type and no members.

Collections are followed too: `{% for post in posts %}` types `post` when `posts` comes from `findAll()` / `findBy()`, a `{# @var posts Post[] #}` comment, or a member whose docblock says `Post[]` or `Collection<int, Post>` (so `{% for comment in post.comments %}` works, also through `|slice`, `|reverse`, `|sort` and `|filter`). Loop variables are scoped to their `{% for %}` body. Go to Definition (⌘B) on a member of a typed variable, in Twig and in PHP, jumps to its property or method, including ones declared in project parent classes. More type sources: `$this->` inside a class offers its own members of every visibility and the public and protected ones of project parents; `$container->get('app.mailer')` follows the service id (and aliases) to the class declared in `config/**`; query-builder chains such as `$repo->createQueryBuilder('p')->…->getQuery()->getResult()` give a list of the repository's entity (`getOneOrNullResult()` / `getSingleResult()` give one), and `$em->createQueryBuilder()->select(…)->from(Post::class, 'p')` the entity named in `from()`. Hover on a typed member or variable shows its inferred type (marked as inferred from sources).

Forms: `$this->createForm(PostType::class)` (and `FormFactoryInterface::create()`) types the form; passed to `render()` as `form` or `form.createView()`, Twig completes `form.` with the fields the form type adds in `buildForm()`, `form.title.` with the form view members, `form.vars.` with the usual variables, and follows embedded project form types (`form.address.street`). Go to Definition on a field jumps to its `->add('title', …)`. In PHP, `$form->get('…')`, `has()` and `remove()` complete the field names, and the options array of `$builder->add('x', ChoiceType::class, ['…'])` completes the option names of the built-in field type (from Symfony's public documentation) plus those every type has. Custom field types offer only the common options; `data_class`, `block_prefix` and extension options are not read.

## Stimulus, assets, UX components and route parameters

- **Stimulus:** `data-controller="…"` (several names, space separated), `stimulus_controller('…')`, `stimulus_action('…')` and `stimulus_target('…')` complete and go to the controller file. Names come from `assets/controllers/**/*_controller.{js,ts}` (`users/list_item_controller.js` is `users--list-item`).
- **Assets:** `vite_entry_script_tags('…')` / `vite_entry_link_tags('…')` complete the `input` entries of `vite.config.{js,ts,mjs,mts}` and `assets/entrypoints/*`; `importmap('…')` keeps completing `importmap.php` entries; `asset('…')` also completes AssetMapper logical paths under `assets/`.
- **Twig types:** class names complete inside `{% types name: '…' %}` (without the `?` and `[]` decorations) and in `enum_cases('…')` / `enum('…')`.
- **Route parameters:** the placeholders of a route (`/posts/{slug}/{page<\d+>?1}`) complete in the argument array of `path()` / `url()` (Twig) and `generateUrl()` / `redirectToRoute()` / `->generate()` (PHP), once the route's name is known from its definition.
- **UX Twig components:** `<twig:Name>`, `</twig:Name>` and `component('Name')` complete and go to the component class (`#[AsTwigComponent]` / `#[AsLiveComponent]` under `src/**/Components/`, with `name:` and `template:` arguments) or, for anonymous components, to `templates/components/**`. Inside `<twig:Name …>`, attribute names complete from the class's public properties and `mount()` parameters plus `{% props %}` of the template; `<twig:block name="…">` completes the blocks of the enclosing component's template. Components of vendor bundles and ones registered by service tag are not known.

## Tool windows

- **Symfony:** _Routes_ and _Index_ sections (the index lists templates, services and translations by domain); double-click opens the definition. The route list is a flat list: the method icon, the path, and grey text with `[METHOD] Controller` after it. *Filter* narrows the list to one controller (the status line says which), *Clear* restores it, and *Flat/Tree* groups the rows by controller. Row actions: *Copy as curl* and *Create HTTP Request File* (writes `http/<verb>-<path>.http`, needs `project.write`; without it the request is copied). The toolbar cache is bound to its rendered root: actions verify the current root, the unchanged selected fact and membership in the current cached index, and never execute an HTTP request. No request panel beside the list, no gutter icon on the handler. A Processes tab opens the Symfony CLI server, server log and Messenger/scheduler workers in terminal tabs. A gutter icon on route usages (`generateUrl()`, `redirectToRoute()`, Twig `path()`/`url()`) goes to the route definition; renaming a route updates its declaration and every usage. Other kinds have no gutter icons.
- **About:** project path, package name, description, version, the installed Symfony version and the versions of key packages from `composer.lock`, the Composer requirements, whether the compiled container and routes were found, counts of what the source index holds, and which `.env*` files exist (never their values). It runs no PHP; **Run bin/console about** opens `php bin/console about` in a terminal tab.
- **Config / Env / Entities:** container parameter names of `config/**` and the compiled container, with their locations (values are not read); variable names of `.env`, `.env.local`, `.env.dev`, `.env.test`, `.env.prod` and their `.local` variants, with the files defining them (**values are never read into the index or shown**); Doctrine entities of `src/Entity/` and the `dir:` of `doctrine.orm.mappings`, read from `#[ORM\Entity]` attributes: table, repository class, fields with their Doctrine type, nullability and `id`, and relations with their target. Entities expand into their fields and relations; activating a row opens its declaration. Legacy annotations, XML and YAML mappings, embeddables and mapped superclasses are not read.
- **Symfony Profiler:** the **Show Profiler** command or the **Refresh index snapshot** button reads `var/cache/dev/profiler/index.csv`; rendering performs no profiler file reads, processes or requests. URL userinfo is removed; query/fragment presence is shown without their contents; IP and profiler token remain visible only in the project-owned review. Rows do not execute URLs or look up serialized profiles automatically; selected details label the target as a source index row, no collector/profile page. Open/double-click/Enter rechecks the invocation root, current key membership, exact source-file owner, file/byte/parser bounds and a unique current record against its cached physical line and displayed request facts, then opens that index line; unknown, foreign, ambiguous, moved or changed records refuse navigation. The source editor shows the original project-owned CSV. Bounds: the index file is limited to 1 MiB (checked by metadata before and by returned size after reading), at most 10,000 physical records and 16 KiB per record, and retains the latest 100 valid unambiguous main requests; strict single-line CSV (quoted commas/escaped quotes supported); multiline or malformed data refuses the refresh; unsupported IDs and case-insensitive duplicate tokens are omitted. Snapshots are bound to the project root and selected source path in session memory: changing either hides former rows until an explicit refresh; a failed refresh retains only that pair's last-good data, marked **STALE** (missing, denied, unreadable, malformed and oversized outcomes are distinct); switching or losing roots clears the single cache slot; refresh and Open also require the index file's exact current project owner. Filesystem events on the selected source mark rows **STALE**; data is adopted only on explicit refresh. The source is the `profilerIndexPath` setting (default `var/cache/dev/profiler/index.csv`; empty uses the default; a normalized project-relative path up to 4096 bytes / 32 components, never absolute/traversal/glob) or a project-owned override stored by **Choose project CSV source** (blank input removes it; discovery lists owned existing CSV files plus the bounded compiled-container files, uses file metadata only, deduplicates shared cache directories and always asks; invalid values hide cached data and refuse Open, never silently falling back to another source). **Inspect Profile** uses the selected request, or asks for one: the optional `process:php` executable runs `php -n` with a 64 MiB memory limit and a two-second execution limit, without bootstrapping the application or loading Composer; raw and GZIP file-storage profiles are bounded to 1 MiB input and decoded data, a 32-level serialized-data limit and at most 128 collectors; only collector names, types and a fixed allowlist of nonnegative numeric metrics enter the UI (headers, request payloads, SQL, messages and arbitrary strings are withheld); PHP 8+ and built-in zlib are needed for GZIP; seven-column legacy and eight-column `virtual_type` CSV are accepted, only request profiles are shown; missing/denied tools or malformed profiles leave inspection unavailable.

## Commands

- _Symfony: Warm Up Cache_ / _Symfony: Clear Cache_ run `php bin/console cache:warmup` or `cache:clear` (optional `process:php`, trusted projects only), then reindex, because the compiled files hold the routes and services of bundles.
- _Symfony: Reindex Project_ rebuilds the index. Saving a PHP file under `src/`, a template or a translation file updates only that file in the index. Adding or removing such a file, or changing `config/`, `composer.json`, `webpack.config.js`, `importmap.php` or the compiled cache files, rebuilds it.
- Templates under gitignored directories (for example `vendor/acme/bundle/templates` added through `twig: paths:`) are not listed, because the host skips ignored paths.
- _Symfony: Run Console Command..._ runs a `bin/console` command in a terminal; _Symfony: Go to Route..._, _Go to Service..._, _Go to Console Command..._ and _Go to Template..._ jump project-wide.
- _Symfony: Make..._ lists `make:*` commands (from `bin/console list make`, or a built-in list), asks for the name and options, and runs `php bin/console make:…` in a terminal (optional `process:php`).
- _Symfony: Create Twig Template..._ explains how to invoke the reviewed **Create missing Twig template…** intention on a quoted Twig reference; _Symfony: Extend Twig Template..._ inserts the `extends` tag; _Symfony: Insert Form Rows from a Form Type..._ picks a form type of the project and inserts `form_start`, a `form_row` per literal `->add('name')` and `form_end` at the caret.
- _Symfony: Find Source Occurrences_ starts from a plain literal route, service or template reference under the caret, requires a known source declaration, scans fresh project-owned PHP/Twig/config YAML text for admitted reference contexts (comments, raw blocks, escaped/dynamic literals and other reference families are excluded), rechecks the original editor and chosen source before navigation, and offers exact file/line/column navigation. It publishes no automatic Rename/edit graph. Bounds: 500 files, 128 KiB per file, 8 MiB total, three seconds and 512 occurrences; skipped, unreadable, oversized or capped sources are labeled **Partial**. The results are physical source-pattern candidates, not a complete runtime usage set.
- _Symfony: Copy Route as curl_ and _Symfony: Create HTTP Request File for Route_ act on the selected route row; _Symfony: Show Profiler_ opens the Profiler tab; _Symfony: Configure Twig Namespace Paths_ opens the path-hint table below.

## MCP tools

Nine read-only project tools return compact CSV from the cached source index (nothing runs PHP): `routes`, `services`, `commands`, `templates`, `parameters` (names only), `entities` (class, table, repository, fields, relations) and `env` (names and defining files, never values), each with `query`, `offset`, `limit`, `template_usage` (controllers rendering a template, and templates that extend, include, embed, import or use it) and `profiler_requests` (token, method, redacted URL, status and time from the profiler's CSV index file). Per-request profiler details run project PHP and are not offered as a tool; Twig extension and Doctrine/form tools are not provided either.

## New file templates

New menu entries for a PHP class with a fixed `App\…` namespace: Command (plain, invokable, with argument and option, with `#[Argument]` / `#[Option]`), Controller (attributes, annotations), Form Type, Twig Extension (methods, attributes), Kernel Test, Web Test, Event Subscriber and Voter. Compiler Pass and Service Config (YAML/XML/PHP) files are created through the reviewed file actions below instead of templates.

## Reviewed file creation

File-creating actions are lazy FileActions with exact resulting-file confirmation: they require the current recognized root and full cached index, matching source version/text and bounded source/target reads, re-run duplicate/prototype/target checks after the review, write nothing while preparing or cancelling, and refuse oversized previews rather than truncate. Values and tags are source-based suggestions, not runtime truth.

- **Create missing Twig template…** (native intention, on a plain quoted template name in `{% extends '…' %}`, `include`, `embed` or `use`, with no trailing expression/options): offers an empty file or a named body-block scaffold, confirms the exact source/version, conventional `templates/` destination, content and line endings, then applies one atomic non-overwriting Create and opens the new file. Target: a validated relative ASCII `.twig` name (at most 512 bytes, 255 per segment) under the project's `templates/`; empty/dot/traversal segments, absolute or URL paths, backslashes, dynamic strings, namespace/bundle names and arrays are refused; existing files/directories, dirty targets and non-directory parents are refused (host stat canonicalizes in-root symlink targets, so not every symlink is detected; sandbox root confinement applies); missing parents are delegated to the host Create. The source scanner skips comments, complete print strings and raw/verbatim bodies (source limited to 128 KiB); provider discovery uses positive cached membership only and checks the actual filesystem and dirty buffers. Configuration discovery is capped at 33 paths; supported YAML is limited to 64 KiB and rechecked after prompts; an explicit `default_path` must resolve literally to this project's `templates/`. Alternate roots, Twig namespace settings, imported/flow/alias loader mappings, PHP/XML loader configuration or layered `config/**/twig.*` files are outside this subset. It infers no parent template or neighboring block names, and covers no PHP render calls, include functions/options, macros/imports, namespace mapping, service-class or Kernel generation.
- **Add service definition to services.yaml** (code action on a concrete project class): appends to the first existing `config/services.yaml`, `.yml` or `.xml` (no file is created) named arguments for the constructor's parameters without a default (services for class types, empty literals for scalars) and, without `autoconfigure: true`, the tags the class implies. Not offered for a class already defined or covered by a `resource:` prototype. In a YAML service file: _Resync arguments with the constructor_ (named `$arg` entries only; keeps existing values, adds new parameters, drops removed ones) and _Add tags …_; in an XML service file: _Add arguments from the constructor_ and _Add tags …_ (argument service ids are the type itself, or the only service whose class is the type). Generation reads at most 32 owned supporting files of 32 KiB each.
- **PHP class creation** (contextual FileAction in an owned PHP class document, or from the root `composer.json`): a plain sibling service class or an empty `CompilerPassInterface` implementation, with a class-name input and exact full-file confirmation. It requires exactly one matching production Composer PSR-4 string mapping among at most 64 validated entries (Composer JSON ≤ 64 KiB, duplicate decoded keys rejected; directory arrays, fallback namespaces, ambiguous, absolute/traversal/dot and autoload-dev-only mappings unsupported), matching source class/filename/namespace/directory, cached class-name collision and vacant-target checks, then one atomic non-overwriting Create/Open. The compiler pass uses fully qualified framework names and infers no framework installation, services, tags, constructor arguments or Kernel registration; the service scaffold is deliberately empty.
- **Service Config (YAML/XML/PHP)** (from the root `composer.json`): a plain filename directly under `config/` and an explicit mode — defaults only, or loading a selected production PSR-4 mapping (the existing owned source directory is verified, with autowire/autoconfigure, the selected namespace/resource path and that root's `Kernel.php` exclusion; paths are encoded per format, nothing guessed). One atomic non-overwriting Create/Open after exact confirmation; LF/CRLF follows the source; no imports, invoking-source edits or Kernel registration are added; whether the file is loaded and which runtime services result remain unknown.
- **Twig namespace path hints** (the _Symfony: Configure Twig Namespace Paths_ command): a table of namespace, relative directory and Enabled for project-owned editor hints (empty namespace = main), with Add/Edit/Remove and Save/Cancel. The form previews the absolute target and labels every row as plugin metadata, not effective runtime loader configuration; saving changes only optional plugin storage (records carry the full project root, schema version and bounded rows; a conflicting concurrent save stays unsaved with a message). Enabled paths must exist under the invoking root with every component a directory; absolute/traversal/glob/parameter paths and empty segments are refused. Bounds: 32 rows, 64 ASCII namespace bytes (letters, digits, underscore), 512 path bytes, 16 path components, 255 bytes per component, 32 KiB stored JSON; unknown schema fields, duplicate namespace/directory pairs and mismatched stored roots are refused rather than rewritten; optional storage denial shows an explicit error. The legacy global `twigNamespaces` scalar (comma-separated `name=directory` pairs, empty name = main namespace, added to `twig: paths:`) remains readable with the same checks and is separate from this table; its changes require explicit Reindex if no relevant filesystem event occurs. Validated enabled hints augment completion and definition navigation with a "runtime loader unverified" origin: scans are bounded to 128 files per mapping, 1,024 total and a 250 ms budget; conflicting logical names are suppressed; missing-template warnings are suppressed while hints or unknown hint configuration could change resolution. Loader ordering, namespace types, imported configuration and runtime loader truth are not reproduced.

## Hover

Bounded hover shows a **cached declaration candidate** for a recognized literal route, service, template or translation key: positive index facts of the current project only, no provider-time file reads, scans or network access; the deepest known cached project root is used, so a sibling or nested project cannot borrow another project's facts. Missing names and ambiguous templates stay quiet; a cached declaration in the current edited file is suppressed rather than showing an older version of that source; partial indexes are marked; cache age, runtime and type resolution are unknown; no translated text, parameter values or service secret values are displayed; a single known route definition can show its declared path/methods (duplicates do not acquire a guessed unique route). Bounds: exact current-literal UTF-16 ranges, 128 KiB and 4,096 Twig code regions/literals. Quiet contexts: Twig/HTML comments, raw/verbatim contents, HTML text and quoted expression text; PHP comment/outer-string contents, heredoc/nowdoc/backtick bodies, dynamic/interpolated/escaped literals; unproven XML namespace-qualified ownership (XML hover needs a namespace-aware element model first); YAML service references are limited to quoted source shapes under `config/`. Translation hover resolves the exact literal call domain, a single known template-level Twig default-domain directive, or the standard `messages` fallback only when a domain was omitted; explicit dynamic/missing/duplicate domains, incomplete calls and lookalike filters stay quiet. PHP lexical masking excludes heredoc/nowdoc bodies (ASCII labels up to 128 bytes, quoted/plain headers, indented closes and CRLF) and backtick literals while preserving byte positions and line breaks; unfinished or unsupported literal headers consume the remaining source conservatively; doc-route annotations come only from lexical doc comments.

## How it works

Everything is matched textually: a call is recognised by its method name, not its class, and templates are looked up in `templates/` and the `twig: paths:` directories of `config/packages/twig.yaml`. Facts are cached per open project from bounded reads of the project's own sources; `vendor/` is not read. Filesystem batches account for created/modified/removed paths and rebuild an affected open project once per batch for conventional source/config roots or any enabled mapped subtree (including ancestor directory deletion; missing mapped directories stay watched so later creation can recover). Unrelated paths do not rebuild the index; closed-project caches are pruned. Oversized batches (over 1,024 events/paths or a 4,096-byte path) drop cached facts rather than retain a truncated stale result; reopening a source or explicit Reindex warms them again. Compiled-cache invalidation covers the four built-in route/container inputs read under `var/cache/dev` plus the configured `compiledRoutes`, `compiledContainers`, `extraServiceFiles` and `extraRoutingFiles` paths (each comma-separated field bounded to 32 KiB, 128 paths and 4,096 bytes per path; no absolute, empty/dot/traversal segments, backslashes, colons or control characters; invalid entries are ignored), including paths outside conventional source folders. When the current root's source settings have changed, cached facts are rejected and live diagnostics run on an empty partial index: current-document checks continue, cached cross-file facts are unavailable until the next event batch or explicit Reindex (the main view offers Reindex). Cache admission marks glob errors, cap-sized results, required read failures and expired build budgets as partial; a cold nested root cannot borrow a parent's cache. Hover and cached definition compare the selected cached root with the current host ownership of both the invoking document and the cached declaration; cold nested projects, closed roots and newly foreign declarations stay quiet (metadata-only, under the declared `project.read` grant).

Capabilities: `project.read` is required; the optional `project.write` (Create HTTP Request File), `process:php` (cache warmup/clear, console, make and profiler inspection), `process:symfony` (Processes tab), `events` (cross-file refresh on open/save), `editor.read`/`editor.write` (Extend Template), `clipboard` (Copy as curl) and `storage` (path hints) degrade gracefully when denied. Settings: the public directory, extra compiled container and route files, extra service and routing files outside `config/` (`extraServiceFiles`, `extraRoutingFiles`), a switch for the practice hints (`practiceChecks`), extra Twig namespaces (`twigNamespaces`) and the profiler index path (`profilerIndexPath`).

## Not implemented

These rely on PhpStorm's PHP, Twig and YAML PSI and full type inference, which the OpenIDEA plugin API has no equivalent for (member types are inferred textually, see above):

- Doctrine DQL strings and QueryBuilder field completion, serializer, form `data_class` and extension options;
- the remaining inspections and intentions (they need resolved PHP types);
- refactorings, find usages, automatic Rename, MCP tools for Twig extensions, Doctrine and forms, the profiler's per-request collector panels (headers/bodies, DB/logger/Twig collectors, remote profiler, runtime execution);
- Doctrine `JOIN ... WITH` to `ON` and QueryBuilder `clearParameter`: no public deprecation notice to build a rule from; `@Template` docblock completion (legacy annotations); run configurations;
- Twig runtime loader resolution (ordering, namespace types, imported configuration) and automatic usages/Rename anchors.
