# Kube Explorer

Browse a Kubernetes cluster from OpenIDEA through `kubectl`: switch context and namespace, list and act on resources, apply or validate manifests, and render Kustomize and Helm output. MIT; see `LICENSE`.

The chosen context and namespace are passed as `--context` / `--namespace`, so your kubeconfig is never modified. To use another kubeconfig file (or several), set it in Settings › Plugins › Kube Explorer; otherwise kubectl uses its default.

## Services tree

- Double-click a context or namespace to switch to it, and expand a kind to list its resources. One stable `kube:cluster` parent labelled **Kubernetes — selected context** groups the tree, with the selected namespace in its detail; root expand/collapse only changes presentation (it discovers nothing, changes no selection and issues no kubectl call).
- The toolbar acts on the selected resource: Describe (or double-click), YAML, Logs (pods; for Deployments, StatefulSets, DaemonSets and Jobs, the logs of all their pods), Shell, Attach, Debug (`kubectl debug -it` adds an ephemeral container on the image of the `debugImage` setting, `busybox:stable` by default, targeting the pod's first container), Port Forward (edit the `local:remote` ports, then Start) and Delete (confirmation required). Editing and terminal workflows open the existing Kubernetes panel or terminal; native read-only details stay beside the Services tree.
- **Custom Resources** lists the cluster's CRD kinds (`kubectl api-resources`, without core and built-in groups) by API group; expanding a kind lists its instances, which take Describe, YAML and Delete like any resource.
- **All namespaces**, the first entry of the Namespace list, shows every namespaced kind as `namespace/name` rows, and an action on a row runs in that row's namespace. In that mode Create Secret, Apply Manifest, Apply Kustomization and Delete Manifest Resources are refused (pick a namespace first), and custom resources that are cluster-scoped or whose name is not a DNS name are listed but take no action.
- If kubectl cannot be started and no context is stored, the tree offers a How to Install kubectl button. Without the `process:kubectl` grant, a non-resource Kubernetes status row explains the missing grant and the private import workflow; selecting it shows read-only help and activates no cluster.
- Context menus follow the row kind: common Describe/Edit YAML/Delete, pod Shell/Attach/Debug, workload logs, supported port forwarding and Secret actions (Create Secret in a single namespace); inactive context and namespace choices offer Switch, groups offer Expand/Collapse and Refresh, and the root exposes Watch and Kubeconfig submenus. The toolbar shows applicable native icon buttons with tooltips; secondary pod/log actions use the More Resource Actions picker. Actions validate the current scoped row key and refuse stale keys, mismatched kinds, changed targets/scope and foreign-view callbacks.

## Resource details

Selecting a resource offers native **Resource**, **Describe**, **YAML** and **Events** tabs where supported. Describe/YAML/Events run only when opened, with bounded request timeouts; Events target the exact built-in kind/name and row namespace (unknown custom kinds do not guess an event kind). Secrets omit the native YAML tab; the explicit Show/Edit/YAML actions keep their reveal gate. Pods and supported workloads offer streaming **Logs** with Timestamps; pods add All Containers and Previous Container, and workloads aggregate their pods and containers with source prefixes and a bounded concurrent stream count. The native host cancels the active stream when its pane is hidden or its target changes. Watch preparation requires an invoking project and a single namespace.

## Secrets

- **Show Secret** (a selected secret) decodes its values in the plugin and shows them only in the panel. It is off until `allowRevealSecrets` is turned on; while it is off, YAML on a secret is refused too (that YAML holds the base64 data), and Describe, which prints no values, still works. With it on, YAML on a secret is allowed and is not stripped: it opens in the panel, read-only, and is never written to a temp file. Show Secret never sends values to notifications, logs, storage, the clipboard, temp files or command arguments; a value that is not UTF-8 is shown as base64. Revealed values clear on Back and when the setting is turned off (the SDK has no view-close event), which also clears cached Secret YAML and retires its page Apply token.
- **Create Secret** builds an Opaque Secret from a name and key/value pairs (Add Key for more than one) and runs `kubectl create -f -` with the manifest on stdin, so values never appear in arguments and no last-applied annotation is written; it fails on an existing name rather than overwriting. Keys are limited to `[-._a-zA-Z0-9]`. The form has no masked field in this plugin API, so typed values are visible on screen; it is cleared on submit or Back.
- **Edit Secret** (a selected secret or the context menu; needs `allowRevealSecrets`): a form of the decoded keys — edit values, add a key, or list keys to remove, then Save. The Secret is read as JSON and sent back with `kubectl replace -f -` on stdin with only `data` changed, so labels, type and `resourceVersion` stay and a change made in the cluster since the form was opened is refused (nothing is saved; open it again). Binary values are kept unchanged and not shown. Values are visible on screen, as in Create Secret.
- Secret JSON reads are bounded to 2 MiB with strict JSON/object/depth validation before any plaintext or form is published; data keys must be unique supported Secret keys (up to 4096), and repeated data members refuse. Show/Edit responses must identify a v1 Secret with the selected name and a concrete valid namespace matching the selected namespace when explicit; Edit requires a nonempty resourceVersion before building replacement authority. Data decoding requires canonical padded standard base64 (CR/LF wrapping allowed): truncated groups, misplaced/excess padding, nonzero trailing bits and other whitespace refuse instead of silently producing changed editable bytes. Raw failed-command diagnostics, including process-level errors, are withheld; safe Conflict/AlreadyExists messages and numeric status remain, and failed forms stay available for retry. Secret YAML failed read/Apply diagnostics are also withheld.
- Revealed values larger than the native multiline field's 1 MiB limit are shown as numbered Unicode-safe parts with explicit join-without-separators instructions (a large binary value's base64 can exceed the limit even when decoded bytes fit); no partial field is silently presented as the whole value.

## Log Viewer

One `kubectl logs --tail=N --timestamps` snapshot of a pod or workload (`logViewerLines`, 1000 by default; at most the newest 2 MiB and 5000 lines shown) in the panel. Filter… (text, or a regular expression with Regex on, matches highlighted), Match case, Since… and Until… (a UTC date or time: bounded ASCII prefixes with valid calendar fields — date, hour, minute, second or up to 9 fractional digits, optional trailing Z; a date or minute prefix includes that whole precision unit; timezone offsets and leap seconds are outside this client-side filter; invalid, Unicode or reversed input is rejected before replacing the last accepted filter, keeping the snapshot and prior display), Wrap, Time and Source (show/hide the timestamp and the `[pod/container]` prefix of each line), Scroll to end, Clear, Refresh, Copy (the shown lines on the clipboard, optional `clipboard`) and Download… — the shown lines, as displayed, through optional `project.write` to a new file inside the owning project, by default `<project>/<kind>-<name>.log`. The confirmation identifies the exact path, line/byte count and SHA-256 of the displayed snapshot; it is a digest review, not a truncated full-content preview. Outside/nested-project paths, existing files, dirty/open buffers and missing parents are refused; Cancel writes nothing; no `tee` or new cluster request runs for export; new files have normal filesystem permissions and may contain sensitive log data. Timestamp comparison pads an absent fraction with zero; malformed timestamp-like payloads remain ordinary text and are not stripped by Hide Time. Following a log stays in the terminal (Logs, Select Log Sources…).

Each snapshot requires an invoking project with `project.read` and records its project, captured context/resolved namespace, a noncredential local configuration fingerprint and the selected source; a different or unavailable project, changed selection, namespace, context or kubeconfig choice drops it before rendering, Copy, Download or Refresh (deactivation too). Refresh is a separate event that verifies the current local mapping still matches the snapshot and reads with the captured explicit context/namespace; an unconfirmable or changed mapping clears the snapshot, and a failed read retains output only after matching owner/scope verification, marked as a failed refresh. Rendering performs no log or configuration discovery. Log and export controls are correlated with the exact loaded snapshot and retire on reopen or successful refresh. Scroll to end relies on the page's script, which the IDE may block.

## YAML editing and private copies

- **YAML** opens in the existing editable panel by default. With `yamlInEditor` enabled, supported modern built-ins open in a private SDK-storage editor copy with the schema modeline; Secrets and unsupported identities remain in the panel.
- **Save is local only.** Invoke **Review Private YAML Apply…**, review the exact target, editor revision, byte count and digest, then invoke **Apply Reviewed Private YAML** in the same editor within 60 seconds. That separate event rechecks project, local kubeconfig/context/namespace and unchanged current text/version, consumes the approval and sends the reviewed text on stdin with `kubectl replace` (UID and resourceVersion are retained and cannot be edited, so server conflict checks still apply). Successful apply consumes the lease; reopen the object before applying again. Review cancellation, expiry, changed source, missing/foreign project, changed local scope and replay do not replace a resource; failed apply consumes the approval but retains the editable copy.
- Copies support stable built-in core/apps/batch/networking/rbac identities only (no Secrets, CRDs or guessed legacy schemas) and are bounded to 64 KiB, one alias/tag/duplicate-free document, depth 16 and 4096 parser nodes; at most 16 live leases and 64 persistent backing files. **Retire Private YAML Editor** removes apply authority and may blank only a generated copy whose current text and backing bytes still match the original digest; edited copies stay. There is no private file-delete API or conditional write/CAS: files remain after retirement, external filesystem races are not excluded, storage is not encrypted or automatically erased, and backups/editor histories can retain contents. Closing an editor is not an observed lease-close event; use Retire or reload/deactivate to release authority.

## Quick fixes

- ⌥⏎ on a manifest: *Add Kubernetes schema* (one-document files of a built-in kind), *Convert List to separate documents* (caret inside a `kind: List` with `items:`) and *Convert documents to a single List* (two or more manifest documents). Both edit only the open file and copy the item lines as written, so comments and CRLF stay; neither is offered when the file has anchors, aliases or Helm actions, when parsed values are ambiguous duplicates, when splitting a List with nonempty wrapper metadata, or when whitespace/chomping changes would alter ConfigMap scalar bytes.
- ⌥⏎ in a v2 `Chart.yaml`: *Add chart dependency* writes a stanza with `NAME`, `VERSION` and `REPOSITORY` to replace; on a `repository:` line, *Use repository alias* and *Use repository URL* swap between a URL and `@alias`. They use the list stored by **Read Helm Repositories for Chart.yaml Quick Fixes** (`helm repo list`), because a quick fix cannot run helm or ask you anything. Aliases whose cached name maps to conflicting URLs offer no conversion; identical rows deduplicate. Chart source edits accept one bounded YAML mapping document without duplicate keys, aliases, anchors, explicit tags or complex keys (8192 nodes, depth 32), preserve trailing comments and CRLF outside the scalar, and refuse unsupported quoted-key or flow-sequence insertion shapes.
- *Use local Helm values schema in YAML language server* adds a relative schema directive for an installed YAML language server, keeping existing directives intact; *Use local CRD schema in YAML language server…* previews an undoable sibling-schema creation and relative directive (it binds resource version/text and source schema, refuses existing/open schema destinations, preserves CRLF and percent-encodes filenames; nullable and int-or-string OpenAPI forms become JSON Schema alternatives). Neither fetches schemas or proves remote schema availability; an installed YAML language server then supplies its own supported semantics. Modeline refactors are never offered to JSON documents.

## Commands

- On the open file: Apply, Validate (server dry run), Diff, Delete Manifest Resources (lists them with a server dry run, then waits for Confirm Delete), Reload Manifest from Cluster (replaces each document of the open file with `kubectl get -o yaml` of the same kind, name and namespace, keeping leading comments; one undo step; needs the optional `editor.write`; a document the cluster does not have is left), Render / Apply Kustomization (the file's directory), Preview Helm Template, Lint Helm Chart and Update Helm Dependencies (the chart around the file; optional `process:helm`). Helm Template revalidates its release argument when consumed, including the fallback chart directory basename and persisted values, so a value cannot become a Helm flag; Lint and Dependency Update do not consume a release argument.
- Update Helm Repositories runs `helm repo update` (optional `process:helm`; if denied, a notification says so). **Read Local Helm Dependency Catalog** reads installed Helm repository indexes explicitly (`helm repo list` and bounded `helm search repo --versions`); it does not update repositories or fetch network data. Repository signatures and current chart dependency identity bind a ten-minute cache, and version completion is withdrawn after dependency identity changes or expiry; updating repository indexes remains a separate explicit Helm action.
- **How to Install kubectl** shows the install instructions in a notification; it cannot install anything. **Telepresence Connect / Quit** run `telepresence connect` and `telepresence quit` in a terminal (optional `process:telepresence`).

## Manifest problems

On open and save (optional `events` and `project.read`; silently off without them). A file is a manifest when a document has both `apiVersion:` and `kind:`; files with Helm `{{ }}` actions only get the Helm checks:

- `deprecated-api-version` (versions removed in v1.16 through v1.27, with the replacement), `duplicate-env-name`, `missing-name`, `missing-selector` (apps/v1 workloads), `chart-missing-key` (`Chart.yaml` without `apiVersion`, `name` or `version`), `chart-unknown-key` and `chart-invalid-value` (a key outside the Chart.yaml schema; a bad `apiVersion`, `type`, `deprecated` or `version`; switch `checkChartSchema`), `helm-whitespace-trim` (`{{-foo` and `foo-}}` in a chart's `templates/`; a trim marker needs a space beside the dash) and `helm-excessive-trim` (`{{-` or `-}}` on an output action that joins a line to the one before or after it; it works on the text, so a `}}` inside a string literal can confuse it).
- `unknown-key` (a top-level key a built-in kind does not have, and, as an Info because a newer Kubernetes may have added it, a `spec` key outside the bundled table), `unknown-kind` (a kind its core, apps, batch, networking.k8s.io or rbac group does not have; custom resources, other groups, `*List`, anchors and Helm files are never judged), `read-only-field` (`status`, `metadata.uid`, `resourceVersion`, …; Info; also `ComponentStatus`, `Binding` and `Eviction`, which are not applied) and `deprecated-key` (`spec.serviceAccount`, `spec.rollbackTo`, `spec.loadBalancerIP`, the `ingress.class`, `storage-class`, `storage-provisioner` and pod seccomp annotations, `metadata.clusterName`, `Endpoints`, `ComponentStatus`, the `Recycle` reclaim policy).
- `missing-key` (an Info: `spec.containers` of a Pod, `spec.template` of a workload that has a selector, `spec.serviceName`, a CronJob's `schedule` or `jobTemplate`, `spec.podSelector`, a claim's `accessModes`, `roleRef`, …; a document without its companion keys is taken for a patch and left alone; switch `checkRequiredKeys`) and `invalid-value` (an Info: a value outside the known set of `restartPolicy`, `dnsPolicy`, Service `type`, the traffic and affinity policies, update strategies, `concurrencyPolicy`, `completionMode`, `volumeMode`, and a non-number or non-boolean in the numeric and boolean `spec` fields; templated values are skipped; switch `checkFieldValues`).
- In a chart template: `helm-unknown-value` (an Info: a `.Values` path whose first missing segment is not in `values.yaml`; quiet for `global`, `tpl`, `with`/`range`/`define` bodies, aliases in `values.yaml`, charts with `dependencies` or `charts/`, and a missing last key next to `default`, `if`, `required`) and `helm-unknown-include` (`include "x"` or `template "x"` with no `define "x"` in the chart's `templates/`). Each has a switch in the settings.

The kind tables cover the core, apps, batch, networking and rbac kinds plus a few of autoscaling, policy, storage, scheduling, coordination, discovery, node, certificates, admissionregistration and apiextensions; the other kinds of those groups are only checked for existing.

## Completion, navigation and gutters

- In an empty YAML document, `kpod`, `kdeploy`, `ksts`, `kds`, `kjob`, `kcronjob`, `ksvc`, `king`, `kcm`, `ksecret`, `kns`, `krole`, `krb`, `kcr`, `kcrb` expand to the manifests of the New-file templates (Pod, Deployment, StatefulSet, DaemonSet, Job, CronJob, Service, Ingress, ConfigMap, Secret with a `stringData` placeholder, Namespace, Role, RoleBinding, ClusterRole, ClusterRoleBinding and CertificateSigningRequest, on current stable apiVersions). In a chart's template, inside `{{ }}`: `.Values.` completes the keys of the chart's `values.yaml` (with `with`/`range` scope awareness for `.Values` and `$.Values`), `include "` the names `define`d in the file and in `templates/_helpers.tpl`, and `incl` an include; unresolved includes are reported as Info.
- In `kustomization.yaml`, `kustomization.yml` and `Kustomization`, root key completion offers documented SIG CLI fields, omits existing keys and replaces the whole partial key, sorted deterministically; nested mappings, values, comments, flow-style documents and multiple YAML documents stay quiet. This does not add full nested schema validation.
- Read-only source navigation and gutters: known Pod/workload paths link ConfigMaps, Secrets, Services, claims and service accounts to cached source declarations and back to source uses. Ingress backend Services/TLS Secrets, Ingress `spec.tls[].secretName` (to a core Secret in its source namespace), valid namespaced-resource `metadata.namespace` (to a core Namespace), explicit metadata namespaces and known HPA scale targets are supported. Arbitrary `data.namespace`, custom `secretName` fields, field-name matches in ConfigMap/custom-resource data and cluster-resource namespace fields do not gain links. Marker tooltips explicitly label read-only source candidates and the unresolved deployment/cluster identity.
- Helm and Kustomize source links: `include`/`template` names navigate to `define`/block names; Kustomization inline patches/replacements target and select selectors (kind, name, namespace, group, version, plain labelSelector/annotationSelector) link to resources listed in the same kustomization, replacement `fieldPath`(s) link to literal keys, and selectors matching none of the fully local parsable resources show an Info; local resources/bases/components directories report a missing kustomization or a bounded-depth cycle; `helmCharts` `valuesFile` navigates to the local file; configMapGenerator/secretGenerator files, `envs`, `env`, replacements path references and Helm template `.Values.a.b` literal paths navigate to exact local files and `values.yaml` keys. Regex, remote, dynamic, quoted-key, flow, merge, generated, indexed and unmodeled forms stay quiet. Block-list resources/components/patch paths offer relative indexed/opened-project-file completion, Go to Declaration and gutters (a unique Kustomization file is required; paths outside the project, remote URLs, ambiguous directory files and nested-project targets are refused; source literals and target existence are rechecked at invocation; provider text is limited to 256 KiB; gutters check at most 16 targets per request).
- Label graph: exact node affinity (`matchExpressions`), pod affinity/anti-affinity and topology spread labelSelector terms are linked; namespaces, `namespaceSelector`, `matchLabelKeys`, `matchFields` and `Gt`/`Lt` terms stay unmodeled. Label-key Rename edits single-line quoted YAML keys with `''` or basic double-quote escapes when the scanned text round-trips to the parsed value; multiline, block, anchored, tagged and `\u`-escaped scalars stay refused.
- **Find Local Label or Data-Key Occurrences** opens a read-only source picker for explicitly namespaced Pod/workload labels, supported complete selectors and named ConfigMap/Secret key references (data-key completion included), revalidating the source version and destination after selection. No cluster process or network request is needed; the cache retains structural facts and source fingerprints, not Secret values. Dynamic/generated identity, absent namespaces, duplicate resource declarations and unsupported scalar spellings withhold authority.
- Cluster-backed hints: **Read Cluster Namespaces for Completion** explicitly queries namespace names for the selected context and local redacted cluster identity (`process:kubectl` and an owning `project.read` invocation; only `namespace/<DNS-label>` output accepted; 64 KiB / 512 unique names). For 60 seconds, exact current `metadata.namespace` values in known built-in namespaced kinds receive positive cached suggestions with UTF-16 replacement ranges and captured context/age labels (documents limited to 64 KiB, output to 200 suggestions; cold, expired, foreign, nested-project, changed-choice, malformed, flow-metadata, Helm-action, alias/tag/tab and unknown/cluster-scoped contexts stay quiet). **Read Cluster Resource Names for Completion…** captures names for one chosen Secret, ConfigMap, Service, PersistentVolumeClaim or ServiceAccount kind in the selected single namespace/project (512 names / 64 KiB per kind, 60 seconds); completion uses them only at existing schema-known reference paths with an explicit matching source `metadata.namespace` and innermost project owner (up to 200 candidates replacing UTF-16 scalar ranges). Both commands may connect/authenticate through kubectl, request names only, retain no object bodies or Secret values, and never run from completion or render; providers never run kubectl. A failed same-owner refresh retires that snapshot; failed foreign reads preserve the prior owner's cache. These are dated metadata hints, not live authorization, namespace existence validation or a link proving a deployment target.
- Navigation works from a plugin-private cache warmed by open, save and file-change events (a file change updates only the files it names): at most 64 source graphs / 8 MiB of accounted graph storage, project-owned YAML inputs up to 128 KiB, and only source names, relationship keys, positions and isolation facts — no Secret payload or full source text. Cache eviction drops the oldest file first and a file change evicts only the named paths; no persistence, cluster calls, kubectl, Helm execution or runtime discovery is involved. Editor requests reparse the current provider text, including unsaved edits, without project-wide scans, and enforce the optional `project.read` grant/ownership; cached target candidates are re-read and reparsed before returning their current range, with a per-call 16-target-file cap plus a shared resolver's 10 ms cooperative read budget and 256-target cap. A target edit/deletion, denied permission, unknown project, foreign root, oversized source or unknown schema yields no affected link; namespace/transform checks run only while warming. The plugin registers no document indexer, so none of these associations enables automatic Rename/Find Usages; they are bounded positive source hints, not complete usage counts or runtime resolution.

## CRD, JSON and values schema assistance

- Indexed/opened local `apiextensions.k8s.io/v1` CRDs contribute structural-schema property and enum/boolean completion for matching group/version/kind resources. Only a unique same-project definition whose current source still matches its indexed snapshot is used; changed, duplicate or foreign-project definitions withdraw assistance. Diagnostics validate types, required fields, enums, explicit additional-property rejection, numeric bounds, string length and supported patterns, collection sizes/uniqueness, read-only and deprecated fields, `x-kubernetes-int-or-string`, null on a non-nullable field (Info: dropped, or replaced by its default; `nullable: true` keeps null), and `metadata.namespace` on cluster-scoped CRDs; ambiguous versions and composition keywords stay quiet. Server admission, runtime defaults, unsupported schema composition, remote references and CEL validation are not reproduced. Cache limits are 64 CRD source files of 128 KiB each; providers do not run kubectl or fetch schemas.
- JSON resources have physical-range built-in key diagnostics and root/spec/metadata completion through the same conservative kind tables, plus duplicate-key warnings; built-in Pod/Service enum choices and local CRD property/enum assistance are available. JSONC comments and trailing commas are masked without changing byte offsets; completion stays quiet inside comments, malformed JSON/JSONC stays quiet rather than receiving guessed structural diagnostics, and UTF-16 locations preserve multibyte source spelling.
- A local chart's `values.schema.json` contributes guarded `values.yaml` completion and live diagnostics; chart dependency fields/conditions/tags also receive local assistance. Provider requests do not run Helm; full chart rendering still uses the explicit Helm template/lint commands.

## Port forwarding and process lifetime

Port mappings are numeric (`8080:80`, `443`, or `:80` for an allocated local port), limited to 16, with valid ranges and unique explicit local ports; named remote ports are outside this form's subset, and CLI flags cannot be entered as port mappings. Both modes explicitly bind `127.0.0.1` and show the target/argv before launch. Scope includes the selected kubeconfig/context, resolved namespace and a fingerprint of the selected local cluster/server/user/TLS/proxy metadata; raw credentials are not retained and no `--raw` config read is made. Rechecking before launch/restart rejects changed selections or context-to-cluster mappings; this is not an immutable kubeconfig snapshot, so a final filesystem/credential race at external CLI launch remains outside the plugin's atomic control.

**Start in Terminal** preserves the existing long-lived terminal workflow; stop it in that terminal — managed controls do not control terminal or external sessions. **Start Managed Session** shows one confirmation with the project, the exact kubectl command and the loopback restriction (the managed draft belongs to a concrete invoking project root, `project.read` required, started with that project as working directory); after you confirm, the forward starts immediately, once the selection, settings and local kubeconfig fingerprint are checked again. Restart needs a stopped session and its own confirmation; replacing a running forward is confirmed and stops only that owned process. Spawn is not a claim that a listener is ready; exits and polling/start failures are shown, and prior output is retained on a failed replacement within the 16 KiB presentation bound.

Managed forwarding is limited to the plugin instance's lifetime: idle reclamation (normally about five minutes), window close, disable/reload and failure end the child process and forget its in-memory status; there is no keepalive loop or automatic reconnect, and the terminal option remains the reliable choice for long sessions. Observed project, resource, context, namespace or kubeconfig changes retire the owned child and require a new draft; status and controls refuse a different project's session, and only the owned handle is stopped. There is one lease per plugin instance, not a per-window registry (same-project windows share it). Rendering polls cached output without invoking kubectl; **Port Forward Status** and explicit refresh revalidate the captured local cluster mapping, each refresh drains at most four bounded chunks, and the displayed tail stays within 16 KiB on UTF-8 boundaries — but there is no reader EOF guarantee, so this is available-output draining, not guaranteed final stream capture, and Stop/retirement may discard remaining output.

## Managed resource watch

**Watch Resources…** chooses Pods, Services or Deployments in one selected namespace and shows one confirmation with the project and the exact kubectl command; after you confirm, the watch starts in the **Kubernetes Resource Watch** pane (`get <kind> --watch --output-watch-events -o json` with pinned context/namespace and a ten-minute request timeout; optional grants `project.read` and `process:kubectl`). Reading drains all available output on every refresh and render, resyncs at the next event after a malformed line, and skips and counts events that are too large. The stream has no trusted initial-end marker, so the pane shows the names seen so far and never proves that a resource is absent.

**Refresh Watch Status** revalidates local scope and drains at most four 16 KiB chunks; rendering does not poll the child, run kubectl or discover files. Fragmented/concatenated JSON is accepted behind strict bounded structure, kind/API, namespace/name/UID and opaque resourceVersion checks; ADDED/MODIFIED update observations, DELETED removes only a matching UID, BOOKMARK is accepted without an assumed interval, and ERROR/410, malformed output, unknown shapes, caps and polling failures release the handle and retain the last accepted metadata as history. Raw object bodies and stderr are not displayed. Bounds are 64 KiB/event, 128 KiB pending JSON, 16 levels / 4096 YAML-guard nodes and 128 observed resources; the view shows at most 32 current and 16 prior names with counts, age and explicit incompleteness, and overflow stops instead of claiming a complete truncated result. **Stop Owned Watch** kills/releases only its stored child; **Review Restart…** starts a new reviewed LIST→WATCH after a separate launch, with prior accepted names kept as separately labelled history (never merged into possibly incomplete new observations); a failed new start retains the previous owned session. Context/namespace/kubeconfig-choice changes retire live state; foreign renders give a safe message without stopping another project's watch; plugin deactivation and lost project access dispose owned state, and there is no durable per-window registry.

## Pasted kubeconfig import

**Import Pasted Kubeconfig (Private, No Connection)** accepts YAML or JSON in a manual multiline prompt, asks for a new label and exact context, then shows a redacted review of profile/context/cluster/namespace/declared user alias/server and authentication mode; a missing namespace becomes an explicit `default` in the saved selected context. Only that context, its cluster and its optional user are normalized and stored. **Review Imported Kubeconfigs (Redacted)** revalidates stored identities and shows the same metadata without displaying tokens, keys or certificate data; labels/aliases overlapping credential material are refused, and errors never include pasted parser excerpts or credential values. **Use Imported Kubeconfig** selects one profile: every kubectl call then gets `--kubeconfig` for it and the Services tree names it (the token and key are never shown or logged); choosing it again lets you stop using it. **Delete Imported Kubeconfig** empties the private file, removes the profile and, if it was in use, the selection. Imported profiles are never merged into configured files or exposed to Choose Kubeconfig. Import, review, use and delete are available without a project, editor or kubectl grant and need only plugin storage: no kubectl/process, network, clipboard, installation, credential execution or cluster validation, and the user's kubeconfig/settings, active context, namespace, Services selection and forwarding scope are never touched.

Supported input is one Kubernetes `apiVersion: v1`, `kind: Config` document with unique named cluster/user/context arrays and valid references. Static bearer tokens, paired inline client-certificate/key data, optional inline CA data and anonymous users are supported, with bounded syntax (not X.509/key-pair) checks. API servers must be HTTPS ASCII DNS names, full decimal IPv4 authorities or bracketed IPv6 literals (compressed, expanded and IPv4-mapped spellings kept exactly), with an optional decimal port 1..65535 and a single terminal slash; no URI credentials, base path, query or fragment. IPv6 zone identifiers/IPvFuture, HTTP, insecure TLS, proxy/TLS-name overrides, impersonation, external credential files, tokenFile, exec, auth-provider and unknown extension fields are rejected — even on unused users/clusters — and YAML aliases, anchors, tags, duplicate/complex keys and multiple documents are rejected before the document model is built. Bounds are 128 KiB input/canonical config, depth 16, 4096 parser events, 64 entries per collection, 32 published profiles, 192 KiB per private record and 4 KiB per redacted metadata record.

Credential-bearing normalized UTF-8 JSON is written only under `host::fs::plugin_dir()` through `write_bytes`; that SDK directory/files are owner-only (0700/private ACL), persistent across reload/restart and removed on uninstall. Generic KV storage contains only redacted metadata and an opaque private-file identity/path. Files use a SHA-256 identity of the complete canonical private record: existing different contents are refused, an identical unpublished record is reused, and both stored bytes and redacted metadata are revalidated before review. There is no exclusive-create/CAS or private-file deletion: concurrent external edits, non-transactional count/label prechecks and cross-file payload/metadata publication are not atomic, and a metadata failure after the private write can leave an owner-only orphan (capped at 64; retrying the identical import can publish it; no automatic orphan removal or credential rotation overwrite). Corrupt identities fail closed and existing profile records are retained. These are plugin-owned profiles, not a native account manager or encrypted OS credential vault.

## Settings

`kubeconfig` takes files separated by commas; **Choose Kubeconfig** picks the one in use (one file, not a merge of them) and resets the context and namespace. `nonKubernetesGlobs` (e.g. `*.compose.yaml, ci/*.yml`) lists YAML files that get no problems. `notifySuccess` turns off success notifications (errors always show). `allowRevealSecrets` gates Secret reveal, `yamlInEditor` private YAML copies, `debugImage` the debug container image, `logViewerLines` the log snapshot size, and `checkRequiredKeys`, `checkFieldValues`, `checkChartSchema` and the Helm checks their diagnostics.

## How it works

`storage` is required. Cluster browsing and operations require the optional `process:kubectl` grant; `editor.read` is optional for editor-related commands, `events` and `project.read` for manifest problems, `project.write` for Log Viewer downloads, `editor.write` for Reload Manifest from Cluster, `process:helm` for Helm commands, `process:telepresence` for Telepresence and `clipboard` for Copy. Denied capabilities degrade: commands stay gated by their own grants, and the tree labels Project or Global CLI mode. Explicit global compatibility remains for browsing with no invoking project, standalone Helm repository operations and unbound forwarding inspection; disconnected kubeconfig import/review, static help/preferences and external global utility commands do not require a project. The existing external-file browsing workflow may use exec-based auth plugins (`gke-gcloud-auth-plugin`, `aws`, …) installed on the IDE PATH; the pasted-import subset rejects executable authentication.

Project-capable browser, resource, Secret and source-command process calls use one explicit invocation project as their working directory (relative kubeconfig settings resolve from that one base), local to the call and never reused as a last-project fallback; a captured project that closes or loses access cannot silently become a global process, and a known invoking project whose identity lookup is denied fails before process or editor actions. Source manifest, Kustomize, Helm chart and Reload operations reject an editor owned by another or an innermost nested project before running a tool or applying a reload edit. Discovered resource types are admitted only as literal DNS plural/group names, never CLI options, and lookup validates again before execution; API-resource discovery refuses malformed/oversized batches (256 KiB / 4096 types) as an error rather than a false empty inventory; single-namespace callbacks reject slash/percent paths, comma target lists, whitespace/control characters, dot segments and leading options (literal RBAC names containing colons remain supported), and bare resource parsing preserves the original admitted name including embedded/repeated `~`.

Cached rich details, revealed Secret plaintext, Secret edit/draft data, pending manifest review, log snapshots and forwarding/watch drafts are bound to a concrete invoking project (`project.read`), the current context/namespace and kubeconfig choice; foreign, missing or revoked identity and scope/choice changes clear them before rendering or stale write actions. Resource rows and mutable controls carry opaque owner/settings-epoch and instance proofs: selection, context-menu commands, native detail requests and old forms retire after project/context/namespace/kubeconfig changes (even with the same literal kind/name), stale callbacks refuse, failed submissions retain current tokens for retry, and long names use short issued IDs or explicit non-actionable rows within the host's 128-byte field-key and 1024-byte tree-ID bounds. Native invocation identity is a per-call snapshot, so a project or credential change after an event begins can still race process start (API 1.3 has no atomic expected-project/client check at spawn), and same-path kubeconfig/credential changes are not continuously watched. These proofs correlate UI state; they do not grant Kubernetes permissions, identify resource UIDs or prove runtime deployment ownership.

State changes refresh both the native Services tree and the packaged resource panel: the panel receives only the model-free `{"channel":"ui-kit-refresh"}` signal, and its hub requests a new model with its own frame, sequence and project identity, coalescing while an action or form field is pending; stable renders emit no further invalidation. Successful panel navigation replaces the prior visible mode (Secret reveal/edit/create, YAML/describe, log snapshot or forwarding review); known unsaved Secret form values refuse replacement until Save or explicit Back, and panel navigation keeps an independently owned forwarding child, watch or private editor. Icons are the Kubernetes logo and Icons Set; tree items can only name icons the IDE knows, so each is declared as a `fileIcons` entry on a pattern no file has and the tree uses its `ext:fileIcon/aritti.kube-explorer/<id>` name.

## Not implemented

- Cluster-backed checks (unknown resources or fields against the live API) and `requirements.yaml` (Helm 2). The built-in key tables cover the kinds listed above only.
- Automatic Rename/Find Usages for any resource kind (the plugin registers no document indexer); full resource-reference completion, deployment-owner closure and CRD namespaces in cluster hints.
- Named remote ports in the port-forward form; durable background watch/forward ownership, automatic reconnect and loss-free backpressure; readiness, live-stream or runtime identity guarantees from snapshots or spawn.
- Export of imported kubeconfig profiles; X.509/key-pair validation; encrypted OS credential storage.
- Server admission, CEL validation, runtime defaults and remote references in CRD schemas; Helm chart schema semantics beyond the explicit template/lint commands.
