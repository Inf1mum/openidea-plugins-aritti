# Spring Boot Tools

Completion and checks for Spring Boot's `application*.properties|yml|yaml` and `bootstrap*` files, and Spring Boot checks in Java and Kotlin sources. MIT; see `LICENSE`.

## Completion

- Key completion: full dotted keys in `.properties`. In YAML, the next segment under the current parent (a property inserts `name: `, a group or map inserts `name:` and a new indented line). Each item shows the property's type, and its documentation gives the description, the default and any deprecation. Map keys hinted by the metadata (`logging.level.root`) are offered too.
- Value completion: `true`/`false` for booleans and the values hinted by the metadata (`logging.level.*` levels, `spring.jpa.hibernate.ddl-auto`…), in both formats.
- Also: logger packages under `logging.level` (from the project's `package` lines), profile names (from `application-*` files) in `spring.profiles.active|include`, keys inside `${…}`, project class names for `Class` keys, enum constants (project enums and the well-known ones), and `classpath:` resources under `src/main/resources` for `Resource` keys and the `spring.config.*` location keys.

## Editor checks

- Deprecated keys: a warning (struck through) that names the replacement. Unknown keys: a warning when a key isn't a property but its parent is a known group of two segments or more (`spring.datasource.urll`). Never reported: keys under maps (`logging.level.*`, `spring.jpa.properties.*`), list items (`[0]`) of known properties, unknown groups (third-party starters, Spring Cloud modules not listed under "Where keys come from", your own keys) and unknown sub-groups of known groups (`spring.datasource.druid.*`, `management.health.consul.*`). The check runs only once the whole project has been read.
- Property values: a warning (`invalid-property-value`) when a value cannot convert to the key's metadata type: `Integer`, `Long`, `Short`, `Double`, `Boolean`, `Duration` (`10s`, `PT10S`) or `DataSize` (`10MB`); an enum the project declares or a well-known Spring Boot/JDK one (`Access`, `Show`, `TimeUnit`, `DatabaseInitializationMode`, `WebApplicationType`…), matched the relaxed way (`safe-mode`, `SAFE_MODE`); a `Class` value naming no class in a package the project owns (library classes are never judged); and the items of `List<X>`, `Set<X>` and `X[]` keys (comma separated, or the items of a YAML sequence). `${…}`, `#{…}`, maps and other custom types are never checked. Setting `springBoot.checkPropertyValues`.
- Cron expressions: Spring's six-field syntax (second minute hour day-of-month month day-of-week), macros (`@daily`…), `-`, `?`, ranges, steps, lists, `L`, `L-n`, `LW`, `nW`, `nL`, `n#k`, month and day names. Checked in `@Scheduled(cron = "…")` literals and in config values whose key ends with `cron` (`app.cleanup.cron`, `app.report-cron`). Placeholders (`${…}`) and SpEL (`#{…}`) are skipped.

## Java and Kotlin checks

- Test constructors: a Spring test class (`@SpringBootTest`, `@WebMvcTest`, `@DataJpaTest`, `@ContextConfiguration`…) whose only constructor takes parameters without `@Autowired` (on the constructor or a parameter, also `@Qualifier`/`@Value`) gets a warning, since Spring autowires them only with `@Autowired`, `@TestConstructor(autowireMode = ALL)` or `spring.test.constructor.autowire.mode=all` in `spring.properties`/a system property; otherwise JUnit fails with a ParameterResolutionException. Quiet until the whole project is read and while any `spring.properties`, `application*`, build file or `gradle.properties` mentions the key. Setting `springBoot.checkTestConstructors`.
- `@EventListener` methods: more than one parameter is an error (Spring throws), a plain `String`/primitive return is a hint (the value is published as a new event). `void`, event objects, collections and async types are not reported. Setting `springBoot.checkEventListeners`.
- `@ConfigurationProperties` classes: a warning for a prefix that is not lower-case kebab-case words (`config-properties-prefix`), a hint for a missing prefix; constructor binding: `@ConstructorBinding` on a component-scanned bean (`constructor-binding-component`, warning) or on two constructors (`constructor-binding-ambiguous`), and an info for several constructors with none annotated and no default one (`constructor-binding-missing`). Setting `springBoot.checkConfigurationProperties`.
- Application setup: a `@SpringBootApplication` class in the default package (`default-package-application`) and a redundant `@EnableAutoConfiguration` or `@ComponentScan` next to it (`redundant-enable-auto-configuration`, `redundant-component-scan`). Setting `springBoot.checkApplicationSetup`.
- Early events: an `@EventListener` for `ApplicationStartingEvent`, `ApplicationEnvironmentPreparedEvent`, `ApplicationContextInitializedEvent` or `ApplicationPreparedEvent` never fires, because those events are published before the context exists (`early-event-listener`). Setting `springBoot.checkEarlyEvents`.
- Test lifecycle: `@DirtiesContext(methodMode)` on a class, `classMode`/`hierarchyMode` on a method (`dirties-context-mode`), and `@BeforeTransaction`/`@AfterTransaction` methods that do not return `void` (`transaction-callback-signature`). Setting `springBoot.checkTestLifecycle`.
- Build files: `Hooks.onOperatorDebug()` gets a hint when `reactor-tools` is a dependency (`ReactorDebugAgent.init()`). Opt-in (`springBoot.checkDriverDependency`, off): an info when `spring.datasource.url` names a JDBC driver no build file declares; transitive drivers are invisible, hence off by default.

The plugin reads source text only (Java and Kotlin sources for classes and enums); bean references in values are not resolved.

## Metadata file checks

`(additional-)spring-configuration-metadata.json` is checked for unknown fields, a malformed `type`, duplicate names, a missing description (hint), a `defaultValue` that does not convert to the `type`, a `deprecation` that is not an object, has unknown fields or a `level` other than `warning`/`error`, a `deprecation.replacement` or hint name that no property defines (info), and a `type` in a package of the project naming no project class. Library classes are never judged. Needs the host to give JSON files to plugins. Setting `springBoot.checkMetadataFiles`.

## Configuration file set

Besides `application*` and `bootstrap*`, a `.properties`/`.yml`/`.yaml` file is read as configuration when a standard file points at it with `spring.config.import`, `spring.config.location` or `spring.config.additional-location` (`classpath:`, `file:`, `optional:`; other schemes and directories are skipped), or by `spring.config.name`. Recognition also follows literal `spring.config.import` chains (import-relative locations resolve against the importing file; fixed `file:`/`classpath:` ones by path tail; `optional:` handled; `configtree:`, placeholders and wildcards refused; depth at most 8, at most 64 files, cycle-safe) and `<name>-<profile>` variants of imported files for literal profiles. One level of the legacy indirection only otherwise. The project search skips dot directories and gitignored paths.

## Navigation, hover and inlays

Go to Definition from `spring.config.import` and from `Resource` keys with `classpath:`/`file:` values (placeholders and other schemes are skipped) to the file, and from a `Class` valued key to the project class. Go to Definition from a `${}` placeholder or a plain key to Java code, and Find Usages between keys and Java code, are not done by this plugin.

Simple `${key}` / `${key:literal-default}` references in current `application[-profile].properties` and `bootstrap[-profile].properties` text navigate to one exact same-file key token; hover gives the source line and explains unresolved profiles, imports, relaxed binding, environment overrides and runtime values. Neither declaration values nor defaults are rendered. Duplicate/missing keys suppress the local target; decoded escaped keys, relaxed alternate spellings, escaped/continued values, SpEL, nested defaults, multi-document properties, YAML and nonstandard imported files are outside this path.

Configuration key hover shows established metadata type, default, description and deprecation, and labels the catalog that supplied the declaration: project-local current/cached metadata, a selected dependency-JAR snapshot (with GAV/scope, archive, entry names and SHA-256 fingerprint, plus an explicit unverified-classpath caveat), or the bundled fallback (labeled as a packaged snapshot with its dataset versions, not the project's resolved version). Configuration inlays show the declared type only. These never report effective runtime values; unknown keys, placeholders, ambiguous declarations and open property prefixes get no speculative hints.

## Commands

- **Spring Boot: Show Configuration Problems** reads every configuration file and metadata file of the project and lists the problems (errors first) in a pick list; choosing one opens the file at the problem. Same checks as the editor diagnostics, without the opt-in JDBC driver hint. Rows are filtered against the current invoking project owner, and current source identity is rechecked before opening.
- **Spring Boot: Read Metadata from Selected Dependency JAR…** reads one JAR after optional `fs.read:~/.m2/repository` is granted, deriving exact paths from supported root `pom.xml` or `build.gradle(.kts)` declarations and showing the project, build file, GAV/scope, version-catalog paths/hashes and selected archive for confirmation. Gradle reads literal `group:artifact[:version]` coordinates (explicit or Boot plugin/platform-BOM-managed versions; ranges, dynamic versions, classifiers and interpolation refused) from the optional read-only Gradle module cache, a notice asks to allow the grant when it is denied. Maven dependency versions may be literal, exact `${property}` aliases from root POM properties, exact root `dependencyManagement` versions, or managed by the root `spring-boot-starter-parent` or an imported `spring-boot-dependencies` BOM (version literal or a same-pom `${property}`; ranges, SNAPSHOT versions and unresolved placeholders refused; parent chains deeper than 4 and more than 32 imported BOMs read refused; in-project parent POMs not followed). Only top-level `META-INF/spring-configuration-metadata.json` and `META-INF/additional-spring-configuration-metadata.json` are consumed; identical normalized records are deduplicated, conflicting cross-document records refused. Project-local metadata wins over selected JAR metadata; selecting a version-qualified Boot/Cloud artifact removes the bundled fallback for that source scope, and absence findings are withheld. Session-only (at most 16 selected artifacts/project across eight project roots, kept until a source POM or build file changes, 32,768-property aggregate bound); saving or opening an unchanged POM keeps them. POM parsing is namespace-aware and bounded: 256 KiB/POM, 4,096 XML elements, nesting 32, 128 direct dependencies, 64 catalog POMs / 2 MiB / 512 offered candidates. Archives: 8 MiB (host cap 16 MiB), 2,048 entries, 256-byte entry names, 1 MiB central directory, 64 MiB total expansion; metadata 512 KiB/entry, 768 KiB combined, 100:1 expansion ratio, 4,096 properties, 1,024 hints, 128 bounded values/hint. Stored/deflate classic ZIP only; ZIP64, encryption, nested/fat JARs, path tricks, duplicate/overlapping entries and inconsistent sizes are refused; length, UTF-8 and CRC verified. SHA-256 records source bytes, not publisher signatures. These are declared catalog candidates, not proof of effective dependency resolution or classpath contents. No classes are loaded.
- **Spring Boot: Current-File Placeholder Occurrences…** (optional `editor.read`): place the caret on a literal property key or `${key}` name; the picker lists the one unique exact property spelling and matching placeholder spellings in the current unsaved file (line and UTF-16 column) and navigates to the chosen range. Reads only the invoking editor; no workspace scan, metadata lookup, network or write. Duplicate or escaped/relaxed spellings, dynamic/nested/escaped placeholder values, multi-document sections and unsupported file contexts stay quiet or refuse. Current text/version/path and project membership are rechecked before opening.
- **Spring Boot: Project Property Source Occurrences…** finds exact raw declaration and placeholder spellings in `application*.properties` and `bootstrap*.properties` files owned by the current project, retaining profile and file provenance. The current editor text is used for its file; other rows describe saved-file source. Values and defaults are not displayed; source identity is rechecked before navigation. Limits: 128 files, 1 MiB total source, 1,024 occurrences; nested registered projects are excluded; unreadable, oversized or unsupported inputs fail visibly. Read-only exact physical-source occurrences, not effective usages.
- **Spring Boot: Run with Profiles/Arguments…** prompts per launch for validated profiles (offering `application-<profile>` files, plus literal profiles named by `spring.profiles.include`, `spring.profiles.group` and `spring.config.activate.on-profile` — plain names or `a | b` only — or declared in imported files) and allowlisted `--key=value` arguments, shows the exact Maven (`-Dspring-boot.run.profiles/arguments`) or Gradle (`bootRun --args`) command, and opens it in a terminal only after confirmation.
- **Spring Boot: Configure Database from Current Source** (optional `database.sources`) reviews an owned native Database source from literal current-editor `spring.datasource.url`, username and password values in one properties/YAML document. Simple PostgreSQL, MySQL/MariaDB, ClickHouse HTTP, Oracle thin service and SQL Server `databaseName` JDBC forms, explicit/default ports and bracketed IPv6 are supported; other SQL Server transport/authentication properties are refused. Passwords go directly to the native secure credential store and are excluded from confirmation text. It does not connect, introspect or execute SQL; duplicate keys, placeholders, encoded/aliased/typed values, embedded credentials, URL parameters and unsupported URL formats require manual setup. If no password is declared, an existing stored credential for the same source is left unchanged; target or user changes create a separately owned source; password rotation retains the same target identity.

Enable `springBoot.nativeRunProfiles` to expose **Spring Boot: Maven spring-boot:run (project build)** and **Spring Boot: Gradle bootRun (project build)** in native Run. Discovery reads only the registered project root's saved build declarations: a direct Maven build/plugins Boot plugin, or a literal applied Boot plugin plus Java, Java Library, Application or JVM Kotlin plugin in the root Gradle plugins block (Kotlin `java`, `application` and `kotlin("jvm")` accessors recognized only in Kotlin builds without a locally shadowing helper). Plugin-management-only, nested, aliased, dynamic, inactive or ambiguous declarations do not establish a profile. Starting the profile runs `mvn --batch-mode --file pom.xml spring-boot:run` or `gradle --console=plain bootRun` in that root (grant the matching optional process capability); discovery never runs a compiler, process, wrapper or network request. Maven/Gradle must be on the host PATH. App arguments, profiles and JVM options come from the project build; this adapter does not infer active profiles, edit saved run configurations or attach a debugger. Native Run owns start/stop/rerun and logs.

## Quick fixes and reviewed rename

- Deprecated keys: a quick fix renames the key (YAML only when the replacement keeps the key's written parent). It inserts only bounded ordinary dotted ASCII key names; a replacement containing property/YAML syntax stays diagnostic-only; an existing target key (including a relaxed spelling collision) prevents the edit.
- Unknown keys: a quick fix adds the key to an existing `additional-spring-configuration-metadata.json` (files cannot be created). It requires complete valid JSON with unambiguous plain top-level fields, at most 128 KiB source and a 256-byte new key, and serializes the key as a JSON string so quotes/backslashes stay data.
- Redundant `@EnableAutoConfiguration`/`@ComponentScan`: a quick fix removes the annotation (explicit supported owners required for both annotations, with the same import/FQN, shadow and current-project source checks).
- **Rename exact static property … with preview** prepares one undoable multi-file edit for an admitted literal key. It inventories host-visible application/profile/bootstrap configurations and conventional Java/Kotlin source roots of the current source module, follows literal local config imports and `PropertySource`/`TestPropertySource` locations, and updates exact declarations and placeholder/`@Value` spellings. Canonical single-import aliases and Kotlin use-site annotations are supported. The confirmation lists every physical file/line/column spelling change without exposing values. Duplicate/relaxed destination collisions, encoded or malformed source, unreadable required local imports and unresolved actual binding ownership withhold the operation; nested YAML renames preserve the dotted parent. Known framework, dependency metadata, local metadata and `@ConfigurationProperties`-bound keys are withheld because renaming their source alone would leave their bindings unchanged. Dynamic/external/environment/`getProperty`/meta-annotation references and nonconventional or host-hidden source roots are outside this static refactor. Limits: 256 files, 128 KiB per file, 4 MiB total, 2,048 edits and the host's exact confirmation size; resolution itself does not write files.

## Where keys come from

- Spring Boot 3.5.16's own metadata (`spring-boot`, `spring-boot-autoconfigure`, `spring-boot-actuator-autoconfigure`) and Spring Cloud 2025.0.3 (Northfields; commons, context, loadbalancer, config, Netflix Eureka, gateway, OpenFeign, Stream and its Kafka binders, circuit breaker Resilience4j, bus, Consul, Zookeeper, Kubernetes, Vault, contract, task, function), bundled in `data/boot-properties.tsv`. Boot's keys win over Cloud's. Regenerate with `python3 -I scripts/gen-metadata.py 3.5.16 data/boot-properties.tsv 2025.0.3`.
- The project's `META-INF/spring-configuration-metadata.json` and `additional-spring-configuration-metadata.json` (project search honours `.gitignore`, so effectively the files under `src/main/resources`, not build output).
- `@ConfigurationProperties(prefix|value = "…")` classes and records in the project's Java sources: the prefix plus the dashed name of each field, record component and setter, one level into classes of the same file. A prefix on a `@Bean` method, or on a class with a superclass, accepts any key below it. Extraction requires an exact fully qualified annotation or one unique canonical single-type import for ConfigurationProperties and Bean (both owners for Bean-method prefixes), and exactly one explicit, unescaped string literal in `prefix` or `value`; concatenation/constant fragments, conflicting or duplicate aliases, escaped strings and text blocks stay quiet. Same-file nested binding follows unique declared enclosing type scopes, plain source and plain non-array field types; imported, qualified, ambiguous or inherited targets stay opaque. Expansion is capped at 512 properties.
- Selected Maven/Gradle dependency JARs (see the command above), which take precedence over the bundled fallback for their source scope.

## How it works

Editor diagnostics use the versioned current-document provider for the Java annotation/cron, metadata JSON and configuration checks. A bounded project cache is warmed during activation and file events; diagnostics, hover and inlay requests read only that cache and the supplied document text. Unsaved edits replace the current document's cached facts; missing, conflicting, dynamic or incompletely read declarations suppress absence-based findings. Requests are limited to 128 KiB of current text, 512 configuration keys, 500 diagnostics and 200 inlays; oversized inputs stay quiet. The current-file placeholder model is bounded to 32 KiB source, 256 keys, 256 references, 256-byte ASCII names and a cooperative 10 ms budget, and requires a currently owning open project; token ranges are half-open UTF-16.

Cached source metadata and live facts are filtered against the current open-project roots (nested projects opened later included): only facts owned by the requesting document's longest matching root are admitted, and the same gate filters completion catalogs, type/package facts, imported configuration recognition, profile/resource suggestions, navigation candidates and the metadata file selected by quick fixes. An ownership-incomplete cached pass cannot establish absence.

Java metadata extraction requires the explicit import/literal rules described above; this proves only admitted explicit source spelling — composed annotations, classpath/module identity and effective binding remain unresolved, and this is not semantic rename authority. Automatic host indexing/Find Usages/Rename of configuration keys remain unregistered: existing YAML paths, relaxed keys and Java-derived binding names are not unconditional replaceable anchors.

Required capability: `project.read`. Optional: `events`, `fs.read:~/.m2/repository`, `fs.read:~/.gradle/caches/modules-2/files-2.1`, `editor.read`, `database.sources`, `process:mvn`, `process:gradle`. Without `events`, checks requiring a complete project view remain quiet. File templates: Spring Boot Application, Spring Boot Test and Spring Boot ConfigurationProperties for Java and Kotlin in the New File menu.

Settings are organized in two native pages: **Java Source Checks** (Tests, Application Events, Configuration Classes) and **Configuration and Metadata** (Configuration Files, Static Metadata, Static Build Facts). All nine boolean keys keep their ids, types and defaults, including the driver-dependency opt-in default; existing overrides continue to apply. The pages link the JAR metadata command; viewing Settings starts no JAR read, scan, process or network operation. These are inspection switches and static-source import controls — environment, Actuator values, effective profiles and metadata defaults are not editable runtime settings.

## Not implemented

Datasource/database tool integration beyond the setup command above, Flyway/Liquibase support, Spring MVC view resolution, the run dashboard's live data (beans, health, environment), SpEL in `@ConditionalOnExpression`, Kotlin configuration classes, repository query preview, AOT/repository-query inlays, effective configuration/Actuator data, and Kotlin configuration-property extraction.
