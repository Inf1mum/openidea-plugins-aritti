# Positive written DTO OpenAPI schemas — 2026-11-11

Scope is source declarations, not effective serializer/runtime validation. New src/dto_schemas.rs is wired into the existing copy-endpoints-openapi command and src/openapi_export.rs. Route facts and schema facts are derived from the same captured per-file text set, avoiding mixed warmed route/source facts. Project reads use current editor contents where provided by the SDK; capture is bounded, not an atomic filesystem transaction.

Primary sources: https://swagger.io/specification/v3/ (OpenAPI3 Schema/Reference/content semantics), https://docs.oracle.com/en/java/javase/25/docs/api/java.desktop/java/beans/Introspector.html (source Bean property design patterns), https://raw.githubusercontent.com/FasterXML/jackson-databind/2.20/src/main/java/com/fasterxml/jackson/databind/MapperFeature.java (public field/getter detection is configurable). No serializer defaults are presented as proven application configuration.

Implemented: Java record components; public nonstatic/nontransient fields; public zero-argument getName/isReady-style getters; Kotlin data-class public property source; simple enum constant names. Exact package/FQN/explicit imports determine source type identity; duplicate FQNs and conflicting explicit imports are unresolved. Builtin primitive/String/wrapper shapes, multidimensional arrays, List/Set/Collection/Iterable and String-keyed Map values are modeled. Recursive object references use stable FQN component keys and placeholders, without dangling references after refusal. Unknown property types retain x-java-type instead of fabricated library schemas. No required-list, readonly or validation inference; Kotlin explicit nullable shapes use OpenAPI3 nullable with explicit type/reference wrapper.

Only declared consumes/produces media become standard content entries. A body/response type with unknown media is exposed in x-spring-source-request-schema / x-spring-source-response-schema rather than guessing JSON transport. View-returning controllers do not acquire response body schemas. Each component identifies physical source path and declared FQN and states its source-shape scope.

Admission/bounds: complete source file discovery capped at10000 per Java/Kotlin glob,256KiB per file,8MiB cumulative,3-second capture budget. Capture failure refuses the export and preserves prior clipboard. Schema depth8,128 components,256 record/field/enum entries and256-byte type/key bounds; arrays bounded4 dimensions. Empty/incomplete Java bodies, inherited/generic/annotated/custom-serialization DTOs, ambiguous namespace symbols and Kotlin alias/typealias package contexts remain unknown. JavaBean acronym getter names are withheld because runtime serializer naming policies differ. Classpath/metamodel types, generics substitution, Jackson annotations/mixins/naming modules, validation groups, effective converter/media and polymorphic/runtime schemas remain explicit adapter work.
